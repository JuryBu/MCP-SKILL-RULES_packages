# 配置、工具升级与发布

本专题的读取事件与时点统一遵循全局AGENTS的「专题阅读入口」。维护工作首次进入时通读，实际修改按已确认职责、目标范围和授权执行。所有本机Git提交均读取并遵循「Git提交来源与身份」。

## 维护职责与默认路线

开工按 engineering-workflow.md 讨论本次升级的完整范围、使用效果、时间资源、额度和用户配合条件。在明确维护职责、目标范围和既有授权内，自主完成调查、候选修复、验证、脱敏发布、受控热切和恢复，不让用户逐项批准常规步骤。主线安排维护与生产协作，不把维护故障丢回每条生产任务各自解决；生产执行任务也不顺手接管共享基础设施。

优先无感更新，验收现有任务、工具调用、消息和持久状态能否无需用户干预地继续。受控后端热切以约一至两分钟为目标，实际排期依据准备、操作、排障和恢复验收所需时间。将本次可靠接入或升级与以后无人值守的自动热切分别约定目标、交付和验收，自动化仅在属于本次约定目标或确有不可替代的必要依赖时作为前置条件。

用户已允许本次手动关开或多次操作时，立即把该条件纳入路线选择，采用已验证的安全入口完成本次目标；自动重开按独立目标继续安排，不能再自行加成手动路线的前提。具体换路、协助窗口和提前准备按 engineering-workflow.md 执行。真正需中断生产、退出应用或重启系统时，先完成离线准备，再说明影响、窗口、回退和用户所需操作，协调后执行，不能先停机再研究。

反复升级造成等待、重启或现场混乱时，在早期提出少量能减少后续负担的结构改进，例如让恢复入口独立于升级对象、复用已验依赖、分开运行进程与控制界面。说明预期收益、实现时间、额外消耗和维护代价，按证据选择最小必要改进，其余另列后续，避免无限扩展自动化工程。

## 切换前准备与失败预案

核实候选版本/commit、真实运行版本、正式入口、完整依赖及修改归属，对照本次约定范围列清准备内容和缺项，区分磁盘文件、安装快照和进程已加载的内容。邀请用户操作前先完成所需准备和入口验证，部分依赖就绪时明确剩余功能及影响。备份被改文件和必要私有状态，记录哈希、版本、文件清单及恢复命令；保留健康旧版本，不能用新版本覆盖唯一可用的回退来源。

回退入口必须在升级对象失效后仍能使用，例如保存可独立运行的恢复脚本或明确命令，不能依赖“等 Codex 打开后让它修”。检查恢复所需的运行时、绝对路径、权限、启动参数与最小工具，避免回退脚本也依赖刚刚替换掉的组件。

尽早做可逆探针，在隔离测试范围内完成正式入口的针对性测试、真实调用链检查和可行的回退演练；运行模式、最终配置、目标 Shell、旧状态、完整依赖和路径差异按工程工作流第六节核验。涉及数据格式、数据库或不可逆状态迁移时，先确认旧版兼容与恢复方式；没有可验证的可逆路线就不伪称可热切，采用隔离迁移或协调明确窗口，破坏性变更须有具体授权。

## 启动与重启后恢复检查

除了“当前进程能用”，还要检查应用正常退出重开和 Windows 重启/登录后的启动链：服务与启动脚本、运行时绝对路径、工作目录、环境变量、端口/PID身份、依赖顺序、加载的配置、凭据与私有状态保留。只核对和修改本次授权相关入口，不擅自调整其它项目的启动项。

先做静态核对和隔离启动验证，不为证明可重启就突然重启用户电脑或共享 App Server。确实需要真实重开/重启验收时提前协调，并标明哪些已经验证、哪些仍待该窗口；未实测不得声称重启后已通过。

分别核对进程能否持续、是否需要交互输入、工具与策略是否授权。支持 detached（脱离宿主进程执行）的 sandbox_launch 可持久保存日志和任务登记；退出 Codex 前后按原 taskId、ownerId、进程身份、日志和退出状态核实能否继续，不能仅凭退出应用推定任务终止。交互输入能力另查，维护入口自设的独立终端条件先核来源、必要性及真实生命周期限制，依据证据在授权内调整，保留有效门禁。

出现明确安全拒绝时立即停止该动作，保留原命令、错误和状态；后续只做安全只读诊断、当前产品支持的可审查审批，或由用户在模型之外明确操作。禁止改包装、更换工具、线程、账号、模型或提权绕过同一拒绝。

临时维护锁、停止标记、激活器和自动恢复任务都要有精确所有权与退出清理。成功、失败、取消和超时路径分别检查，既不能留下“文件已换好但扫描永远暂停”的状态，也不能误删别人的维护标记。

## 受控切换与健康确认

操作分工沿用现场维护对话的完整职责，双机任务按 development-machine.md 执行；本地诊断、适配、依赖及环境准备由现场对话在授权内自主完成。每次需要用户时，指明真实的授权、交互输入或进程生命周期条件、已自行完成的准备和仍需亲自做的动作；可自主完成的常规工作留在现场对话执行。入口自设条件与工具原始安全拒绝分别核对，遵守上节门禁与拒绝边界。

切换前再次核对备份基线是否被他人修改、相关任务与请求是否可保护、端口和进程是否确属目标组件。发现所有权冲突、并发配置漂移或无法保护的在途写入，先隔离和调整路线；不能为了赶窗口强杀或全目录覆盖。

只替换已验证范围，能热加载就不整机重启，需要短暂停服时仅涉及必要组件。新版本就绪后检查真实调用、任务/消息路由、工具可用性和关键持久状态；HTTP成功、版本号变化、文件哈希或进程存在都不能单独证明业务恢复。

给用户的操作说明提供完整可复制块，每块自行定义所需变量、路径和条件，可在指定 Shell 中独立执行。逐步说明复制哪一块、在哪里执行、遇到确认输入什么、接下来做什么、预计等多久，以及失败时如何保留日志和状态、何时停止并从独立入口恢复。获准手动重开时按该路线提供操作，自动重开另按约定验收。

健康门槛未满足就停止进一步切换，核实真实运行状态和失败位置，按预案恢复旧文件、入口和必要状态，再验证旧链路真实恢复。若新版已经完整安装且业务健康，仅确认记录或入口收尾失败，保留现场证据，评估授权范围内接管收尾与回退的实际影响；不能仅凭脚本退出码反复回退，也不能跳过必要验收或伪造完成记录。无法确认回退完成时保留证据并说明，不用“已执行回退命令”冒充成功。不可逆操作、未知是否已执行的动作和付费调用不能盲目重跑。

## Git 提交来源与身份

提交前核对当前仓库 remote、分支、改动归属与用户授权，只提交已验证的目标文件。已有无关修改先隔离，不全部暂存；不为发布擅自改全局 Git 身份，不用 force push 覆盖他人提交。修改前和 push 前 fetch，远端变化后按实际冲突正常整合并重新验证受影响范围。

有机器角色约定时，从已选 profile、对应手册或私有覆盖读取作者名与 `Codex-Machine` 值，保留已绑定邮箱；只在有依据及授权时设置仓库级身份。角色未知先核对，不推断为 development 或 training，也不把发送方的个人名字写成接收方身份。

Codex 提交使用 `Codex-Thread: <当前稳定 conversation_id>`，提交前通过当前宿主任务列表核对。已确定机器标记时同时写 `Codex-Machine: <本机角色或约定标识>`；属于明确双机任务才加 `Codex-Task: <task_id>`，无任务ID不填、不借用历史任务。旧提交缺字段时标为来源未知，不靠时间或同账号强行归因。

这些最小来源字段是公开提交的明确例外，不授权公开对话正文、机器绑定、私有路径、账号和日志。推送前做脱敏检查；发布与本机/其它机器安装状态分别验证，不用公开 commit 证明所有任务已加载。

## 共享源码、脱敏发布与选择性安装

仓库按当前维护对象的真实 remote 和本机维护映射确定，不把一个私有机器路径或统一仓库地址套给所有任务。公共源保存可复用代码、Rules模板、Skills及安装器，本机账号、token、二维码、任务绑定、对话ID、绝对私有路径、原始记忆和完整日志留在私有覆盖。既定 Git 提交来源规范要求的最小标识字段除外，该例外仅用于规定的来源字段，不扩展到对话正文、关联绑定、日志、账号或整份私有 AGENTS。

发布前检查 diff、待提交文件、样例、测试夹具、文档链接及附件中的敏感内容；用可信占位值与最小脱敏证据替换，不能只删账号正文却把身份留在路径或截图。测试和独立审查通过后，在已授权维护范围内主动推送公共修改，不把本机私有 AGENTS 直接当发布源。Git身份及提交来源依上节执行，机器角色值另按对应手册核对。

公开发布、本机安装、其它机器安装和运行验收分开记录。按每台机器和约定的功能或组件逐项说明已准备、已安装、已加载、已验收及各自证据，写清完整清单共有多少项、实际完成多少项、缺项和使用影响。部分安装按实际范围报告，剩余内容明确待办；用户开始手工操作后继续验收实际结果。选择性合并私有覆盖，校验来源 commit 与实际文件内容；对端准备好后经登记的协作通道同步，失败保留待办。各机器、旧任务和同步包的更新状态分别核实。

## 收尾与风险告知

核对实际生效版本、真实调用链、回退资料、激活器终态、自有维护标记清理与必要的开机恢复证据；清理自己创建且已无用途的窗口、后台任务和临时文件，不清理借用资源。需要后续重启验证时明确保留待验收项和恢复入口。

预计无法无感升级时，在切换前说清原因、影响和已准备的安全路线，按已获许可的手工配合及时调整，保留完整升级目标。持续尝试没有新证据时停止无效投入，重新比较路线；确需用户时按前述分工提供已验证操作。整体重大阻塞按工程工作流的通知与保全要求处理。
