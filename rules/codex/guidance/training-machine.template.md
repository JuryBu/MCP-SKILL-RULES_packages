# 条件式训练机运行手册

## 适用范围

本手册只在收到有效训练任务包并完成只读核验后生效。其他时间按普通 Codex 全局规则工作，不把本机永久视为训练机。

训练机负责收包、监督长跑、处理运行故障、严格回包并等待取回。训练机可以主动解决工程问题，但不能脱离主包另立任务目标。

## 生命周期

| 状态 | 允许行为 | 退出条件 |
|---|---|---|
| `NORMAL` | 普通 Codex 任务 | 收到候选训练包 |
| `READ_ONLY_INTAKE` | 阅读、验哈希、核对身份与环境 | 拒绝或确认任务 |
| `ACTIVE_TRAINING` | 启动、监督、调优和受控恢复 | 完成、暂停或失败 |
| `RETURN_PREP` | 验结果、导证据、打包回包 | 双重验包通过 |
| `RETURN_READY` | 等待传回，不再修改正式结果 | 回包被取走或任务关闭 |

## 收包身份门

进入 `ACTIVE_TRAINING` 前逐项核对包哈希、`task_id`、项目、工作区、目标机器、硬件、任务清单和 `ready_to_run=true`。`task_id` 表示长期协作身份，重复运行日期、时间和批次放在 `run_id` 或 generation，不因一次重跑就自行更换任务 ID。任何身份项不匹配都留在只读状态，不创建训练环境、不写正式目录、不启动进程。

## 主包权限与自主判断

主包明确必做的事项必须完成，明确禁做的事项不得执行。存在科学疑点但仍可执行时，照做并记录风险；只有任务相互矛盾、输入身份错误、代码无法实现主包语义、继续运行会污染结果或输出已无法支撑任务结论时，才暂停受影响部分。

暂停时保留原配置、命令、日志、错误、进程信息和最后干净 checkpoint，不顺手替换成自己偏好的实验。停止错误运行是保护任务，不能被误判为擅自放弃整个训练目标。

## 单写者与恢复

每个正式运行记录 `task_id`、`run_id`、PID、命令、输出目录、日志和 checkpoint。启动前扫描同任务活跃进程，同一输出目录只能有一个写入者。

发现旧进程与恢复进程同时写同一目录时，停止较新或错误的一方，把目录标记为污染，从最后确认干净的 checkpoint 恢复到新目录。

Windows 睡眠、更新重启、断电和卡死按正常故障设计。定期保存运行状态、配置、随机种子、进度和 checkpoint，恢复前先核对旧进程是否仍活着。

## 自适应监控

启动后先在 30–60 秒内确认进程、日志和显存状态；早期或不稳定阶段每 5–10 分钟检查，稳定长跑可放宽到 30–60 分钟或更长。

每次检查交叉查看进程、结构化进度、日志时间、checkpoint、GPU 显存与温度、磁盘和 stderr。单次 GPU 低利用率或 stdout 安静不能直接判死，应延迟复查。

## 对话职责与维护交接

训练执行对话负责验包、训练监督、止损、证据保存和任务恢复。公共 MCP、Rules、broker、安装器和系统配置由训练机本地维护对话或开发机仓库维护对话负责修复、测试、提交与发布，不能仅凭两者运行在同一台机器就混用职责。

训练执行对话发现基础设施问题时，保存复现步骤、错误日志、相关消息序号、任务影响和已经采取的止损措施，再交给维护对话。未经主人明确变更职责，不在长跑期间转去修改公共仓库；维护对话不可用且必须紧急止损时，只在当前任务工作目录做隔离的临时修复并记录待维护事项。

修复安装后，训练执行对话只验证任务通信、文件传输和训练是否恢复。依赖双机环境的修改由两端维护或验证对话分别实测，另一端暂时不可用时记录待验证项，不阻塞本机止损和恢复。

## NapCat 任务路由

真实群、账号、机器映射、token 和路径由本机私有覆盖提供。缺少或不匹配时不启用自动路由。

固定群迁移必须与对端约定带时区的绝对切换时间。切换前短暂停止结构化发送并处理或留证旧群待确认消息，备份私有 binding 后原子更新群身份；保留 open task、代次、游标和冷却状态，验证新群与路由正常后再恢复，失败立即回滚。

进入任务对话后调用 `napcat_task_register`，显式登记 `task_id`、稳定 `conversation_id`、`local_role=training`、来源/目标机器和可信对端。需要更换整个任务时，两端先登记方向兼容的后继任务并完成握手与消息验证，再以 `successor_task_id` 关闭旧任务；最终结束则确认 pending/active wake 为空、开发机已完成最终交接并显式声明 `final_close=true`。关闭后的任务不会继续接收提醒，不能先关旧任务再等开发机联系。

后台路由只接受固定群、已登记任务、正确目标机器和可信发送者同时匹配的消息。`message_seq` 不保证数字递增，同一扫描内多条消息按消息时间与群历史顺序合并，只唤醒绑定对话一次。

收到 `[NAPCAT_TASK_WAKE]` 后，当前对话调用 `napcat_read_recent`，按需下载文件；提示中的 `new_message_seqs` 是本次新增，`previously_pending_message_seqs` 是此前仍未完成的待办。实际处理完一条或多条后，用同一 `wake_id` 调用 `napcat_task_ack`，在 `processed_message_seqs` 中只列出已完成的消息。旧唤醒的迟到 ACK 只确认所列消息，不能顺带清除后来消息。

结构化文本和文件索引发送后，用 `napcat_delivery_status` 区分 `machine_received`（开发机扫描到）与 `conversation_received`（开发机 Codex 对话收到引导）。它们是自动传输回执，不代表业务完成；只有对话处理正文后提交的 `napcat_task_ack` 才能清除 pending 消息。

旧任务意外关闭时调用 `napcat_connection_request` 提出重新建链。首次请求显式传本机 `source_conversation_id` 和已知的开发机 `target_conversation_id`，开发机校验可信机器后持久保存回拨地址；之后任一端可用 `reply_to_request_id`，或用稳定 `previous_task_id` 自动恢复该地址，不需要主人再次远程提供。双方对话 ID 只出现在建链控制消息中，普通任务消息、文件索引和 heartbeat 不重复携带。该请求只唤醒，不替开发机登记任务；双方必须各自核对并登记建议任务、互发握手，确认新路由后才恢复正式协作。需要主人知晓、判断或协助时，先登记当前对话的 owner route，再向 binding 预配置的私聊或通知群发送简短人话；不要把训练日志、字段块或内部 `route_key` 倾倒给主人。主人在私聊引用该通知回复，或在群聊引用并 @ 本机账号，系统才把回复送回当前对话。

任务唤醒的 UI 可见性由私有 binding 的 `codexWakeMessageVisibility=visible|hidden` 控制，默认 `visible`。路由器每次唤醒前重读该字段，修改后从下一次唤醒起生效，无需重启；`visible` 会为消息附带稳定标识，忙碌轮次中模型可先收到，但 Desktop 气泡可能等当前阻塞工具返回后才渲染，`hidden` 保留无独立气泡的旧行为。

没有新消息时不按计时重复发送旧提醒；有新消息时，任务级冷却结束后只合并唤醒一次，并同时带回此前仍待处理的消息。短时间连续到达的新消息不得不断推迟这次提醒。模型可以通过 `napcat_task_update` 调整当前任务的 `wake_cooldown_ms`，但不能跳过可信身份、代次和 ACK 约束。

监督器只在 broker、正确账号 OneBot、NapCat 进程、Codex 进程和 open task 都满足时运行任务路由。快速登录失效时进入人工二维码恢复，不把「进程存在」误当成账号在线。

Heartbeat 只表示长跑存活，不等于任务 ACK，也不负责恢复 Codex 对话。

## 文件与回包

收到任务文件索引后，核对同一 `task_id` 的原始 `file_id/fileUuid`、可用的 `file_message_seq` / `busid`、文件名、大小、发送者和 SHA256，再下载并重新计算哈希。若 NapCat 重启后第一次文件 URL 查询失败，允许工具按消息序号刷新群历史并重试一次；兼容旧索引时，只能按固定群中同一发送者、文件名、字节数和五分钟内相邻附件受约束地恢复真实 `fileUuid`，不要改用来源不明的 URL。

主人、任务 manifest、工具调用参数或本机/当前任务已有稳定目录约定时，严格沿用该位置，不启用默认下载规则。只有这些来源都没有给出位置时，有任务代次就下载到当前任务根目录的 `intake/g<generation>/`；没有任务代次时使用 manifest 中明确的轮次目录，不得把 `<generation>` 等占位符当成真实目录名。

不得为了符合默认目录而移动、复制或重复下载已经落盘的文件。新下载完成后在 Task/manifest 中记录绝对路径、原始 `file_id/fileUuid`、`file_message_seq` / `busid`、字节数和 SHA256，原始包保持只读，解压与修改放进对应的 `work/g<generation>/` 或 manifest 指定工作目录。

正式回包完成双重验包后，先预览路径、文件名、大小和 SHA256，再上传固定任务群。上传结果、文件标识、索引状态、去重键、大小和哈希写入回包 manifest。

打包后把 ZIP 解压到新的空目录，以开发机刚收到包的视角重复验证路径、内容、对话身份和哈希。ZIP 的 SHA256 放在压缩包外部。

回包禁止夹带 QQ 登录态、NapCat token、broker 私密环境、浏览器 profile、缓存、临时文件、旧任务对话和无关大文件。

## 退出

训练完成、任务拒绝或回包传回后停止当前 heartbeat，调用 `napcat_task_close`，写明最终状态并退出训练模式。
