# 开发机双机协作手册

## 适用范围

本手册只在存在明确双机任务时生效。日常开发、文档、检索和普通工程任务仍按通用 Rules 工作。

## 私有覆盖

公开仓库不保存真实账号、群、机器映射、token 和运行路径。安装后由接收者创建私有覆盖文件或环境变量，至少提供：

- 本机逻辑角色与机器名称
- 对端逻辑角色与机器名称
- 本机 NapCat 账号与可信对端账号
- 固定群 ID、群名和预期成员数
- OneBot URL、token 与本机运行目录

缺少这些值时，只允许预览、只读检查和人工传输，不启用自动发送或定向唤醒。

固定群需要迁移时，两端先约定带时区的绝对切换时间。切换前短暂停止结构化发送，读取并处理旧群待确认消息；备份私有 binding 后在约定时刻原子替换群 ID、群名和预期成员数，不关闭或重登记现有任务。切换后核对账号、群身份、路由和 open task，失败立即恢复备份。

## 主包准备

主包必须包含稳定 `task_id`、项目身份、目标机器、文件清单、SHA256、必做项、禁做项、允许调整项、暂停条件、完成条件和回包要求。

开发机在发送前从新的空目录复验主包，确保没有混入登录态、对话数据库、浏览器 profile、运行日志、旧任务产物和无关大文件。

## 任务登记

发送端和接收端都必须调用 `napcat_task_register`，使用相同 `task_id` 并显式填写各自稳定 `conversation_id`、`local_role`、来源/目标机器和可信对端。

任务换对话时使用受控更新并增加 `generation`，旧对话不能继续读取或 ACK 新代次消息。任务完成后调用 `napcat_task_close`。

## 消息与文件

文本和文件索引都带 `task_id`、来源机器和目标机器。普通群聊、其他任务、错误目标或非可信发送者不得进入当前任务。

文件索引记录原始 `file_id/fileUuid`、可用的 `file_message_seq` / `busid`、文件名、字节数、SHA256 和可下载标识；不得把只对发送端 NapCat 当前进程有效的根文件临时 `file_id` 当作跨机索引。接收端下载后必须重新计算大小与哈希，不以「接口返回成功」代替文件验证。兼容旧索引时，只能按固定群中同一发送者、文件名、字节数和五分钟内相邻附件受约束地恢复真实 `fileUuid`。

`message_seq` 是不保证数字递增的消息标识。收到 `[NAPCAT_TASK_WAKE]` 后，绑定对话调用 `napcat_read_recent` 获取当前任务未确认消息，处理到提示中的 `pending_through_message_seq` 后，使用该原值调用 `napcat_task_ack`，不得自行取数字最大值。处理租约内后续到达的消息进入下一批队列，不会改写当前唤醒的确认令牌。

## 问题回收

训练机报告问题时，开发机先区分任务包错误、环境差异、运行故障和 MCP 工具缺陷。能够继续科学任务时，不让工具缺陷无故阻塞训练；需要修复时由一个维护源统一修改并重新发版，禁止两台机器各补一套不兼容代码。

## 对话职责与维护交接

双机协作按对话职责分工。训练执行对话负责训练监督、止损、证据保存和任务恢复；开发机或训练机的维护对话负责公共 MCP、Rules、broker、安装器和系统配置的修复、测试、提交与发布。

训练执行对话发现基础设施问题时，提供可复现步骤、错误日志、相关消息序号、任务影响和已经采取的止损措施，再交给维护对话处理。未经主人明确变更职责，训练执行对话不得一边监督长跑一边修改和发布公共基础设施。

复杂修改由独立 Codex 对话或子代理审查。依赖 Windows、NapCat、登录状态、路径或双机通信环境的修改还要在两端分别实测；另一端暂时不可用时记录待验证项，可以先发布已完成本机验证的紧急修复。

## 文件下载默认位置

主人、任务 manifest、工具调用参数或本机/当前任务已有稳定目录约定时，严格沿用该位置，不启用本节默认值。仅在没有任何明确位置或既有习惯时，有任务代次就下载到当前任务根目录的 `intake/g<generation>/`；没有任务代次时使用 manifest 中明确的轮次目录，不得把 `<generation>` 等占位符当成真实目录名。

跨机文件索引必须保留原始 `file_id/fileUuid`、可用的 `file_message_seq` / `busid`、文件名、字节数和 SHA256，不得把发送端 NapCat 当前进程里的根文件临时 `file_id` 当成跨机下载标识。接收端下载后记录绝对路径并重新计算字节数和 SHA256，不以接口返回成功代替验证。

不得为了符合默认目录而移动、复制或重复下载已经落盘的文件。原始下载保持只读，需要解压或修改时放进对应的 `work/g<generation>/` 或 manifest 指定工作目录。开发机私有账号、群、token、路径和运行状态不得进入公共仓库。

## GitHub 协作

可复用问题先搜索已有 Issue。新功能、长期问题以及跨机协议、公开接口、数据格式和安全边界变更应登记 Issue 并优先通过 PR；小型文档、测试、明确修复以及主人授权的紧急修复，可以在完成 fetch、针对性测试、来源标记和脱敏检查后直接提交。

## 回包验收

回包在新空目录解压，逐项核对任务身份、对话身份、运行配置、结果、日志、checkpoint、指标、哈希和主包要求。发现缺失、污染或错对话导出时停止发布，保留证据并要求补包。

通过验收后再进入公开仓库维护流程，执行脱敏、构建、测试、独立审查、commit 和 push。
