# 设计与文书：面向实际读者与视觉品味制作（Antigravity 2.0）

本专题遵循全局 `GEMINI.md`「专题阅读入口」：当需要制作或改写网页前端页面/组件、独立设计、3D 场景、海报、PPT、Word/PDF 报告、讲稿或正式说明前读取。具体格式实现配合 `frontend-design`、`pptx`、`docx`、`pdf`、`canvas-design` 等对应 Skill，渲染与截图核验遵循 `guidance/web-visual.md`。

## 一、先确认受众、场合与本机参考素材库（正例在前、负例在后）

1. **受众与文体分清**：先确认谁会看、在什么屏幕或场合看、看完要理解或决定什么。正式报告、学术文档、对外说明与机构文稿按实际读者身份书写（**清除聊天口癖、表情符号、内部阶段代号、审核黑话、裸对话 UUID/编号前缀及「后台的隐藏传话」式自造怪词**；面向用户的说明从上次交流共识位置接起，直说可用功能与现实待办），把核心结论与必要背景按自然阅读顺序讲明白，禁用「不是X而是Y」「不代表」式防御性叠甲与「首先、其次、最后」模板腔。
2. **本机风格参考素材库流程（若接收方已在本地配置）**：
   - 创作视觉界面、海报、PPT、3D 建模、文风或短文本前，若接收方本机已配置参考素材库（例如 `C:/Users/<USER>/<style-reference-library>/`，具体路径写入本地私有覆盖），**先读**该库根下的 `README.md` 与 `总索引.md`，按本次载体与受众挑选少量相关**正面案例**，**完整精读入选案例的说明文档（如案例说明与制作流程文档）**（只看目录名或只扫一眼图片不算已读，人类说明是借鉴点与取舍边界的首要依据；案例中的渲染预算、缓存预计算等性能设计也须同步纳入首版规格，禁只抄外观漏掉优化），再看原图/成品。
   - **创作前铁律**：正式成稿完成前，**严禁读取负面库、`负面参考索引.md` 及任何负面案例**，防负例污染创作直觉。
   - **成稿后排雷铁律**：初稿/完整页面制作完成后，**必须打开对应专题的负面参考核对排雷**，检查是否踩中同类布局、配色、句式或质感雷区，发现即改并重验渲染。
   - 撰写长中文正文或关键文案且接收方本机配了私有中文表达例库时，必先按文体只读对照 1～2 份原稿与改写样例校准语感（不修改该目录，也不将私有案例发布入库）。

## 二、样稿先行、去大模型味与表达细节

- **重大视觉方向先定样稿与离席完整交付**：用户在场且新设计方向未明确时，先做少量贴近真实比例与内容的代表性样稿（如首页关键视口、PPT 封面+1张典型内容页）供确认，不在方向未定时一口气把几十页成品做死；若用户已离席休息且已给完整交付目标与正例库，按正例说明定准方向后直接完成完整初稿与负例排雷，严禁只交样稿停工空等。展示多张候选图或成品时，**逐张输出清晰原尺寸单图**（除非明确要求对比拼图，否则禁止擅自拼成低分辨率多宫格缩略合集图掩盖细节；向用户展示与交付只用原尺寸高清原件、禁拿检视副本顶替，调 `read_file` 自检多图/音视频/PDF 时按 `web-visual.md` 走小件原生直读、大件 `scratch/` 不损信息减体切页或短命子代理直读即 `kill`，防主线全量请求体重传拖慢）。
- **多路并行生图备选、子代理分工初筛与交互克制原则**：需要原创配图、海报底图、PPT 插画或参考图局部编辑时，积极委派（含**同一回合多路并行派发产出不同构图/色调备选**）内置 `invoke_subagent(TypeName="image-generator")`（Nano Banana 驱动，精确文字加引号，参考图传 `ImagePaths`，成品直存 `brain/<id>/`），严格遵守「先读正面参考说明 → 逐张原尺寸单图检查挑优 → 成稿后对照负面库排雷」闭环。长文档校对、多案例索引提取与逐页视觉初筛**严禁主线单打独斗**，积极并发 `Hydrogen XHigh` 做素材定位对账、并发多路独立 `Neon XHigh`（极端复杂或关键定稿用 `Carbon High`）分担文案推敲、负例排雷与零背景读者挑刺。派发子代理后主线同步推进骨架、文案或验收准备并先完先检，严禁派完挂空等。日常汇报严守效率优先，优先用紧凑大白话表格或文字（进度表按用户大白话任务主干分栏，严禁照抄 `Task.md`/`Plan.md` 内部批次/阶段代号或函数名），仅在视觉对比或多参数联动确比表格/文字直观得多时才用图文混排或 `<agent-embed>`，严禁倒贴十分钟手搓花哨网页。
- **拒绝 AI Slop 模板味**：不为凑工整强套三栏圆角卡片、万能渐变紫底、三字排比标题或「从 X 到 Y」套话；先定信息层级与视线动线，再定字体、配色变量、留白与克制有意义的动效。
- **页面、交互产品与 3D/动效的首版流畅度及内存/显存预算**：
  1. **常规网页与交互产品 UI**：首版实现即把响应丝滑与低内存占用当硬指标——长列表/大表格用虚拟滚动或分页按需渲染，首屏重资源按需懒加载，细粒度状态订阅防止高频局部更新引发全组件树无效重渲染；高频事件（`scroll`/`resize`/`pointermove`/实时筛选）合并至 `requestAnimationFrame` 或做节流防抖，动效优先走合成层属性（`transform`/`opacity`）避免读写 DOM 交错触发布局抖动（Layout Thrashing）与大面积重绘；切路由/重搜或组件卸载时用 `AbortController` 取消旧异步请求，并彻底清理事件监听、定时器、`Observer` 与大缓存引用，防止竞态错乱与单页产品越用越卡。
  2. **Canvas / WebGL / 3D 与富媒体场景**：首版规格同步锁定高分屏像素面积上限（按视口×`devicePixelRatio` 封顶渲染像素，防 2K/4K 屏带宽雪崩）、离屏 FBO 数量与尺寸预算、着色器循环与内联展开上限（防 Windows ANGLE D3D11 冷编译黑屏数十秒及每帧 ALU 过载，高频噪声优先烘焙纹理 LUT）、非截图时刻关闭 `preserveDrawingBuffer` 保障双显卡零拷贝呈现，并在页面隐藏（`visibilitychange`）或暂停时挂起 `rAF` 与 `AudioContext` 释放 GPU/CPU。
  3. **禁牺牲观感的假优化**：优化耗时或帧率时，须保证画面各可见动态层（背景、主体、粒子、UI）更新帧率协调一致且核心画质零暗降，严禁把某一可见运动层粗暴分帧降成几帧每秒的肉眼跳卡来换平均帧耗时数字。
- **PPT 专项硬约束**：① PPT 页面文案禁止把三个「主语+动词+宾语」串成同构动作句；② PPT 页面文案禁止句号，并列关系用换行、间距或分组呈现；③ PPT 标题问句只允许设问或反问；④ 正式大制作按「排版前两项独立检查（内容增删 + 推进顺序与造句）+ 完成后两项独立检查（对照参考说明与负例看视觉 + 模拟零背景扫看读者逐页挑刺）」执行。

## 三、交付前真实读者复核

交付前以挑剔的零背景读者与真实用户视角通查：脱离聊天上下文能否直接看懂？字号、对比度、遮挡、高光眩光（如 3D 标识/文字是否被 Bloom 泛白洗糊）、边缘黑边与移动端/桌面端视口是否全部经过真实截图确认？网页与交互组件在连续滚动、拖拽、缩放、转镜头与状态切换时是否顺滑无卡顿尖峰、内存平稳且切后台/关闭后定时器与音频渲染循环已干净停止？修改任何一处后必须重新截图并复测对应页面，确保最终交付件与验收证据版本 100% 一致。
