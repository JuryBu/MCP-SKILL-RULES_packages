# 工程工作流：分级推进、真实验收、双审与跨端长跑（Antigravity 2.0）

复杂多阶段工程、架构改动、线上服务/规则升级、双端配对或安排独立双审前读取本专题。核心底线：**流程是为真实可用服务，绝不允许用「刷双审、刷子代理、刷单测、刷 Mock 截图」演流程代替真机实测**。

---

## 一、分级推进：日常小修利落做，复杂工程稳扎稳打

### 1. 按真实风险分级（杜绝小修大演戏）
- **日常单点修补 / 3～5 文件明确改动（不涉及运行中服务、代理、核心架构或全局规则）**：直接读透源码 → 改好 → **亲手走真实入口与真实数据验实** → 自己维护的仓库按 `maintenance-upgrades.md` 精确提交推分支盯 CI，不必硬拉 11 步大台账和四轮双审。
- **复杂工程（跨阶段、核心架构改动、改运行服务/代理/规则、多端长跑）**：
  1. **讨论环节最重要（聊透再开工，开工后按常识推进且真有必要敢问）**：先核近况、记忆与源码，把目标、取舍、验收与边界在讨论期聊透；方案尚未定案前不抢跑挂 `stage_guard` 或防断定时。双端讨论期用户跟哪端聊，该端主动找搭档碰撞带回异议同轮整合答复。动工后尽量顺着先前讨论和常识自己拿主意推进，不拿讨论过或常识能定的事反复打断用户；**也别因之前被批乱问就走向极端——真遇关键分歧、外部卡点或不可逆抉择，依然坦荡直问必要问题**。多文件摸底果断并发多路互不重叠 `Hydrogen XHigh` 先遣。
  2. **计划建档与目录隔离**：计划存 `plans/`（`Plan_x/` + `Task.md` 登记双审轮次、未闭环项与待复核项）；已有他端 `plans/` 建 `plans_agy/` 只读不覆写。每个正式阶段走 `stage_guard(start -> 落盘真实证据 -> check)`。
  3. **线上服务物理隔离**：改运行服务、代理、网关或全局配置前，先于 `%TEMP%` 独立副本与端口实测，备 SHA256 清单、独立回退脚本与不依赖被改组件的独立恢复入口，按最小可回退单元连推。
  4. **首版性能与资源回收**：开发产品、网页、服务或脚本时，首版同步控冷启动耗时、热路径复杂度（消 `O(N^2)` 与主线程阻塞）、内存/显存封顶，并在退出/异常时确定性回收子进程、连接、锁、定时器与渲染循环；性能调优靠量化定位主导真瓶颈复测 P99，不做降质假优化。

## 二、真实验收反形式主义铁律（交付前必过真入口）

**核心红线**：单元测试全绿、JS/API Mock 假数据截图、`--silent` 无窗启动秒退、浏览器自检全过、对抗双审全 PASS，甚至 `Stage Guard PASS`，**统统不代表真实使用者用起来没问题**！更**严禁手改测试凑绿、缩容或挑子集重跑掩盖失败用例、或只校验首帧掩盖后续报错**！

1. **必须亲手跑通非 Mock 真实使用全链路**：
   - 桌面/前端/GUI 软件：查清同源全链路做体系根修（不搞出一个修一个的修补式打补丁，不拿表面哈希/单测核对替代真实运行），将**核心业务写路径收口到唯一后端真源**，用真实打包程序、真实后端、真实配置与真实点击交互走完核心动线（含高 DPI 拖拽与窄窗），并以**真实脏旧配置跑跨步骤状态链黑盒验证（如旧配置迁移→删订阅→导新订阅→启真实二进制/真内核）**，覆盖真实非 ASCII 路径与线上配置（不拿干净单步、`%TEMP%` ASCII 假夹具、静态假 Bridge 或一次性外挂脚本充数）；交付前确认桌面无黑屏与残留报错弹窗；
   - 监控/数据/脚本工具：必须拉真实多天历史库与真日志做异常分布统计，不能只跑自己编的 1 条理想单测；
   - 跨平台项目：推送常规分支后必须盯完云端多系统 CI 真实绿灯，红灯立即自修；
   - 3D/文书/视觉成品：必须回归「像不像、好不好懂、有没有 AI 腔/晕字术语」的零背景读者第一眼直觉。
2. **大改后必重验**：最后一轮改码、改文案或改配置后，受影响视角与真入口必须重跑重截，旧证据绝不顶替新版。
3. **放手交付前先替醒来的用户查一遍（硬拦截伪收工）**：凡用户放手交给单端或双端推进的任务，在停下来汇报或交卷前，执行方与审查/排期子代理必须先站在「用户刚回来查进度」的视角追问两件事：① **还有没有根本不需要用户开口就能接着推进的后续步骤？** ② **如果用户现在按真实眼光多查两句，会不会当场冒出我们自己本就能提前查出来的漏洞、坏状态或可顺手清掉的遗留？** 只要有一条答「是」，就当场继续推透修净再交卷，严禁半截停工等用户回来随口说两句才发现还能继续或这里不行。
4. **汇报讲人话总进度（绝不写让人不想读的公文流水账）**：答进度或交卷时从用户上次实际参与处接起，用大白话直讲「整体现在做成什么样、真能用的功能、还差什么、真卡点」，不堆砌公文流程词（「已完成实证归档、回执与办结确认」「守约与静默边界」）、文件名轰炸、裸 UUID、内部批次代号或底层函数名（无需为一句短追问硬跑 `scratch/` 写草稿）。

## 三、并发调度、真并行与独立对抗双审

### 1. 真·完全并行与单端主攻
- **破除「派完即挂 `wait`」**：派发子代理同拍锁定并推进无冲突自留活（隔离夹具、回退脚本、独立模块、核态），**先完先检、已落盘子件先检**；仅当自留活做空且仍在等子代理时，挂 `schedule(DurationSeconds=120～180, TimerCondition="any")` 查 `transcript.jsonl` 防假死（`swarm_wait` 仅 worker 用）。
- **无配对或对端停机转单端主攻**：停离线对端 `*/30` 巡查改单干 `*/8` 防断，建本端 `plans/`（或 `plans_agy/`）跑满并发——`Hydrogen XHigh` 摸底 → `>=2` 互不重叠模块首选同工作区独立文件边界拆多路 `Neon XHigh`（纯编码用 `swarm`，需 MCP 用 `invoke_subagent(TypeName="self", Model="inherit")`；共享仓不用 `workspace:"share"`，非共享仓 `share` 须合回主工作区验完再 `kill`；极端核心升 `Carbon High`）→ 独立双审 → 真入口验收。

### 2. 两项独立对抗审查（重质不重量）
- **何时派审**：真正复杂工程在**改生产前（初方案/隔离候选成型后）**与**最终交付前**各委托两名上下文独立的审查子代理（默认 `Neon XHigh`，关键定稿可升 `Carbon High`）并行挑刺。流程强度与双审锚定未交付原始总目标——中途小插步不归零双审；**但也绝不靠连刷十几二十轮双审自我感动，审完闭环采纳项就把精力投入真机实测！**
  - **审查 A（原话、长期原则、排期与伪收工拦截）**：直核用户无封套原话与近况第 1+2 层，首要**替刚回来查进度的用户拦截伪收工**——查有没有无需用户开口就能接着推的步骤却提前停手、有没有漏掉旧核心要求、有没有把真问题后置成假依赖、有没有违背常识或排期拖延。
  - **审查 B（真实性、防 Mock 与醒后必踩坑清扫）**：预设「存在脑补路径、单测 Mock 掩盖真 Bug、宣称真机实测实为静态假桥接、进程/句柄泄漏、残留机械停等、越界改动，或用户回来随手一查就能暴露的明显漏验与边界坑」，逐项核源码行号、真实命令输出与最新实测证据，挖出本可自查却没清掉的遗留。
- 采纳项当轮改实并重验；拒采写明理由；闭环后立即 `kill` 回收。需跨模型找盲点时主代理可直调 `sandbox_codex` 或 `sandbox_council`。

## 四、防断续接、压缩恢复与安全收尾

1. **周期防断（`schedule` Cron）与精准停用**：
   - 复杂长工程第 1 拍挂 `schedule(CronExpression="*/8 * * * *", Prompt="...")`（`5～10m`，紧急可 `*/5`），`manage_task(list)` 记 `TaskId`；专作断网/流超时兜底，不主动等闹钟（平台级 `Error Unknown` 缩间隔无效；恢复先核原 `TaskId` 防 `list` 瞬态漏显叠挂）。
   - **完工、仅差用户操作/拍板、外部真阻塞、或用户明确暂停/停止**时，最终回复前同拍 `manage_task(Action="kill")` 并 `list` 读回已停，同时把 `update_steps` 全标 `done`/`skipped`。**用户明确暂停高于一切唤醒与搭档建议**。
2. **压缩与唤醒双锚点回读（严防「重读规则锁回不打不动」）**：
   - 遇 `<CONTEXT_SUMMARY>`、`/compact` 或 `[schedule]` 唤醒时，依赖旧交流前首拍并行读：`交流近况.md`（第 1+2 层；遇 `Partial read` 续读全）+ `Task.md` + 本文件 + **压缩前 3～5 轮纯净人机原文**（`transcript.jsonl` 倒读或 `conversation_read_original`，先剔 `[COMMUNICATION_CORE ...]` 代理封套、`[schedule]` 唤醒、工具输出与摘要；首批全被代理/唤醒占满则向上扩窗）。
   - **关键核验**：严禁单看 `USER_INPUT` 标签把代理转述当用户原话（核正文无封套与前后问答）；更**严禁因重读通用规则就把用户早已给过的常规授权（自研仓直推、外部 IM 通知约定、已撤前置）锁回去变成「不打不动」**！未入近况的新原则/转向当轮补录。
3. **高水位防自动压缩超时 & 健康体检**：上下文达 `380k～430k`（按窗口比例折算）备近况提 `/compact`，`>=440k` 慎新发大批重流。已配本地监测时在批量调用中顺手体检（不单挂定时），仅持续退化或真实配额告急时降流，不凭步数参考线或瞬时波动砍并发。
4. **`%TEMP%` 清理护栏**：不把 `%TEMP%`/`scratch/` 当唯一持久存储；只按精确归属路径清本任务自建临时目录，绝不按年龄批扫整个 `%TEMP%`。

## 五、双端配对长跑、常识互补与复联

1. **整块交付、双向排期互审与独立决策**：
   - 优先级：**`用户 > 对口伙伴 > 子代理`**；交流视同用户，原权限不变、明确暂停不由搭档恢复。
   - **按可独立验收整块切活**（不把搭档切碎当帮把手），接手自主定序，搭档仅作外部意见非逐段放行人；验收点前只就真依赖、小事实询问、写窗交棒、低额委托或重大路线变更对齐，其余直推。双向鼓励对方直指拖延、切碎或不合理步骤。
   - **双向保长板（主动跳脱找更优方法，同时绝不破坏对端优点工作流）**：对对端细致取证、边界严谨、隔离实测与整块稳推的优点工程流程保持尊重与顺畅配合，**不用急躁催促、拆碎任务或粗放拍脑门破坏对方长板**；同时自身绝不被对方节奏裹挟成一条路走到黑——遇四类情况必须**主动跳出当前执行框架，从全局和常识审视有没有更直接、更省事、从根上更好的做法**，温和直说并果断拉回主线：① 陷入局部修脚本/盖章拉扯超 2 轮/30 分钟（算清真实时间与额度账主动刹车）；② 路线卡住或越绕越复杂却有更短替代路线（可主动独立接走某项验证，不跟着对方小步逐段代审）；③ 用户已拍板需求遭条件反射过度安全审查改歪阉割；④ 能靠子目录、前缀或受控边界解决的隔离却被硬加多余假前置（如逼另建新群）卡死全线。放手长跑期间双端互审亦共守「不等用户回来点破才接着推或补查」。
   - **主动盯额度与横向串联历史**：有约定额度重置阈值时，低余量阶段每次协作顺手核一眼并提前提醒对端，别耗尽停摆；排查系统性问题必**横向关联近期全机活跃对话的真实历史现场**，不做孤立单点修补。
2. **离线转单端与 `reconnect-sync.md`**：对端停机或耗尽离线时停重发、停 `*/30` 转单干 `*/8` 切单端主攻，在计划目录维护 `reconnect-sync.md`（`pending_sync|synced`、预设 `dedupe_key`、改动路径与哈希、旧 `unknown` 处置）；顺手 `get_status` 探活见可投递后免催首拍按原键补发改 `synced`。
3. **半小时巡查与离席决策**：离席巡查挂 `*/30` 读对端真实增量与变动文件比对原总目标——平稳静默不越位重审；可推却停（排除明确暂停与真必等）区分排期加锁或早停（识破预告当交付、拿待查停工、单线拖全线、同源挤牙膏四类逃生门）带证据促续；离席期间遇可逆权衡，在既有授权内**按用户目标与常识果断拍板**；完工、暂停或仅余真必等时停 `*/30` 并读回。问题按归属分口报双端 RULES 主线。
