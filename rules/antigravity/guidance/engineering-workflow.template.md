# 工程工作流：共识、隔离、排期、独立双审与防断恢复（Antigravity 2.0）

本专题遵循全局 `GEMINI.md`「专题阅读入口」：长期或复杂工程（预估 `>10 分钟`、跨阶段、涉及线上服务/网络配置或派发多路执行与审查子代理）开工、接手或恢复前通读，执行中按阶段复核，普通单次问答与小修不强套重流程。

## 一、开工共识、边界核实与物理隔离铁律

1. **先调查再定方案（先遣探路阵列先行，讨论期不改代码）**：从本对话 `主人交流近况.md`、工作区记忆与已有交流确认原始意图、完整交付范围、验收方式、用户作息窗口及不做什么；已明确内容不重复问卷式提问。**告别主线单打独斗硬啃材料**：估时和提方案前，一旦涉及多文件排查、读历史对话/日志、尚有未知依赖或存在「可查可不查」的疑点，立即从不同来源、模块职责、旧失败记录与替代路线等角度拆出多路互不重叠的 **`gemini-4-hydrogen-xhigh` 先遣探路子代理**（预期发现少也果断派，不自行压缩人数）并行取回原文入口、精确行号与可核事实，保护主线上下文不被大段杂讯撑爆压缩；主线同步处理立即可查的阻塞点并亲读关键证据收敛方案，严格区分「已核实事实」「合理推测」与「待验证假设」。
2. **线上服务与关键配置物理隔离演练**：凡涉及正在运行的本地服务、本地网络代理/网关内核、守护进程、全局配置或持久数据的改动，**开工与测试必须在系统 `%TEMP%` 独立子目录、独立端口与测试副本中完成物理隔离验证**（核实连通性、真实流式吞吐、异常回退与重启恢复），并备妥原文件 SHA256 清单与独立一键回退脚本；未经隔离实测通过与用户确认，**严禁热改线上运行配置拿正常使用链路当试验田**。
3. **目录、多端与同端并发防撞约定**：
   - 新项目计划默认放入项目目录 `plans/`（`plans/index.md` 总索引 + `plans/Plan_1/`、`plans/Plan_2/` 细化方案 + 可勾选 `Task.md`）；若目录内已有其它端的 `plans/` 或 `plans_codex/`，本端自觉建立 **`plans_agy/`**（及 `主人交流近况_agy.md`），绝不覆写他端文件。
   - **公共多项目根工作区防相撞**：在公共多项目根工作区开新工程时，优先落入 `<独立项目/任务子目录>/plans_agy/`；若直接在根下且已有在跑异主题 `plans_agy/index.md`，则按 `plans_agy/<主题短名>/` 子目录隔离，严禁多个并发反重力会话争用或覆盖同一个 `plans_agy/index.md`。若获授权需协同修改他端既有 `Plan/Task`，须注明 `Antigravity 修改`、时间与原因。
   - `Plan` 写丰满（归档关键路径与参考图防压缩丢失）；单次代码/文档产出超过约 `1 万字` 上限时按模块拆文件或用 `edit_file` 分批增量写入，严禁静默省略；`Task.md` 末尾常设「**待复核/小本本**」，已完成 Stage 压成一行摘要（过程入 `memory-store`），每小阶段走 `stage_guard(start -> 先落盘产物与证据 -> check)` 闭环。

## 二、真实时钟排期与关键路径压缩

预估超过约 10 分钟或多线并行时，核对本机当地时间，在计划中记下开始时间、阶段预算、事故缓冲与下一复核点。按同一时间轴识别真实串行依赖，**把调度彻底跑起来**：调研期多路 `Hydrogen XHigh` 分片扫底 → 实现与深度推演期多路 `Carbon High`（独立文件边界或 `workspace:"share"`）并行攻坚、多路 `image-generator` 并行备选配图 → 节点与交付前多路独立 `Carbon High` 假设驱动抽查与双审，最大化并行重叠，绝不让主线单人串行硬扛或把各步耗时简单相加。

用户已说明吃饭、休息、离开或返回时间时，立即把必须人工决定或配合的事项前移，其余已授权工作由主线独立推进；连续尝试同一思路无新证据时果断止损换路，时间吃紧时只削减可选探索与装饰性整理，绝不削减根因修复、回滚准备和真实入口验收。

## 三、两项独立对抗审查（禁止合并敷衍）

复杂工程在**初始方案成型后（动手改生产前）**及**关键阶段/最终交付前**，必须分别委托**两名上下文独立的审查子代理**并行挑刺（禁止合并成一句笼统的「帮忙看看有没有问题」）：

| 审查角色 | 选用通道与模型组合 | 预设对抗假设与必查重点 |
|---|---|---|
| **审查 A（排期、原话对齐与计划疏漏审查）** | 两路独立 `gemini-4-carbon-high`（或 `invoke_subagent(Model="inherit")`），或 `carbon-high` + `gemini-4-hydrogen-xhigh` 交叉互审 | 预设「主线漏读原话/批注/参考图、尚未吸收最新纠正、存在未验证假设或低效串行空等」。直接核对相关对话原文与 `主人交流近况.md`，找出遗漏诉求、错误依赖与可压缩排期的具体调整。 |
| **审查 B（路线进度、防幻觉与逐行实绩审查）** | 与审查 A 独立会话、互不串供（需调只读 MCP 脚本实测时可用 `invoke_subagent(TypeName="research", Model="inherit")`） | 预设「存在脑补接口/路径、表面单测未测生产真函数、异常分支漏清理（如锁/PID/回滚死角）、未走真实运行入口或混用改前旧截图虚报完成」。逐项核对源码行号、命令真实输出、持久状态与最新渲染截图。 |

- **主线复核与落地闭环**：子代理必须带回具体文件路径、行号、命令输出、支持/反对假设的证据及「未检查范围」（无问题可如实报零发现，不强行编造错误）。主线逐条复核证据：采纳项**当轮实际修改代码并重跑受影响验证**（绝不把「收到审查报告」当成「已修复」）；不采纳项记录具体依据。审查结束核验后立即 `kill` 回收子代理。
- 需要跨模型视角找盲点时，主代理可额外调用 `sandbox_codex`（GPT 重型代码审查，`background=true` + `45s` 短轮询）或 `sandbox_council`（多模型会审，只出建议不执行）。

## 四、持续工程周期防断续接、防压缩流超时与安全收尾

1. **持续工程周期防断续接（对标 Codex Heartbeat，原生 `schedule` Cron 闭环）**：
   - **开工登记与核实**：持续工程主线开工时，必须使用原生 `schedule(CronExpression="*/20 * * * *", Prompt="...")`（周期按工程节奏设 10～30 分钟，保持 `ExactTiming=false` 防拥堵抖动，`IsDaemon=false` 随任务生命周期管理）登记绑定当前对话的续接任务，紧接着用 `manage_task(Action="list")` 读回确认 `TaskId` 与活跃状态，写入 `Task.md` / `主人交流近况.md`（已有同目的活跃 `TaskId` 则直接复用，严禁重复叠挂多条 Cron；登记失败须明确说明缺口，不把口头计划算作已安排）。
   - **执行纪律（严禁摸鱼等闹钟）**：续接任务专用于断网、流超时（如 `stream idle timeout`）、进程抖动或意外中断后的自动唤醒恢复。主线执行期间必须连续推进全部已授权且就绪的工作，显式等待健康子代理并及时收回结果，**严禁主动结束当前轮次把本可立即推进的实现拖到下一次定时唤醒**，也严禁唤醒后只改个检查时间戳不干实事。
   - **唤醒恢复核查与未知副作用防重发**：被 `[schedule]` 唤醒（或网络/压缩中断后恢复）时，第一步先读 `主人交流近况.md`、`Task.md`、`manage_subagents(Action="list")` 与本对话 `transcript.jsonl` 末尾，核对主线、子代理、后台任务的真实状态及既有产物。仍健康运行则继续等待原任务，已完成则收证推进；遇到写入、部署、付费接口或状态未知的在途操作，**必须先查清原回执与实际落盘副作用，严禁靠盲目重发碰运气**。状态未变时静默处理不刷屏，仅在有实质进展、完工、阻塞或需决策时汇报。
   - **结束轮次前四象限状态核对与停用销账**：

| 当前状态 | 主线动作 | 本任务周期续接（`manage_task`） |
|---|---|---|
| 有可推进工作，或健康子代理/后台任务仍在运行 | 继续执行或配合短 Timer 等待原任务，及时整合结果 | 保持有效 |
| 全部准备就绪，只差用户操作/拍板 | 核实真实入口、正常启动、失败回退及同版证据，清晰说明唯一待办 | 汇报前/同轮 `kill` 停用并读回确认 |
| 所有可推进分支已完成，剩余阻塞须外部条件改变 | 核实替代路线与并行工作，保存具体缺口、现场与恢复条件 | 汇报前/同轮 `kill` 停用并读回确认 |
| 已完成、取消或用户明确暂停/停止 | 核实实际结果，落实子代理与临时资源收尾保全 | 立即 `kill` 停用不再需要的续接 |

   - **明确暂停高于一切自动唤醒**：**用户明确说出暂停/停止的优先级高于任何定时唤醒、网络恢复或换号重启**——收到暂停指令立即传达至相关子代理并 `manage_task(Action="kill", TaskId=...)` 停用续接；若残留唤醒抵达而尚未给出新继续授权，核清已停状态后保持静默停止，绝不擅自复工。普通闲聊与无待办单次问答不挂持续续接。
2. **高压上下文防自动压缩流超时（`256k` 硬线 & `5m0s` 保护）**：
   - 反重力宿主 `language_server.exe` 在序列化上下文超过 `MaxTokenLimit = 256,000` 时强制触发 `context_summary` prehook，**直接复用当前主模型（如 `Carbon High`）**请求摘要，且硬编码只读 `5m0s` 空闲流超时；一旦越过 `~235k` 发生 Prompt Cache 归零冷 Prefill，又撞上同窗 10+ 路 `Carbon High` 子代理重并发抢占通道，极易连撞 `5m0s` 超时中断。
   - **主动控流与趁热 `/compact` 规程**：① 大文本/多文件/长日志读取一律拆给 `Hydrogen XHigh` 先遣兵在独立上下文消化；② 持续工程每阶段查看本对话 `transcript.jsonl` 末条 `PLANNER_RESPONSE` 的 `input_tokens + cache_read_tokens` 水位，升至 **`180k～210k`** 时先把最新进展与未决项写进 `主人交流近况.md` 与 `Task.md`，趁阶段间隙主动提醒输入 `/compact`（可附保留重点说明）趁缓存温热秒级完成压缩；③ 主线水位 **`>= 200k` 时严禁同窗新发大批（`>= 4` 路）`Carbon High` 重任务**，须先收敛或压缩后再开重并发。
3. **子代理定期短巡检（防假死与半截睡死）**：主线边做独立工作边每隔几步查看 `manage_subagents(Action="list")` / `swarm(action="status")` 及子代理 `brain/<id>/.system_generated/logs/transcript.jsonl` 末尾步数与时间；当主线自身工作已就绪、需停下等待子代理回包时，挂单次短定时器 `schedule(DurationSeconds=120～180, TimerCondition="any")` 定期醒看——健康推进则续等；读半截文本误入 `waiting` 未发汇报则发消息唤醒补完；卡在同一时间点久无新步、遇地区/容量报错则果断 `kill` 回收，改派 `gemini-4-hydrogen-xhigh` 或由主线补齐。（注意：挂 `schedule` 后须在同一回合附简短说明或随工具回合直接结束，**严禁下一拍发出既无工具调用又无可见字符的纯空响应**，防触发宿主 `ERROR_MESSAGE`；Swarm 协调者可用 `swarm_wait` 零耗能挂起。）
4. **独立辅助对话线程（`agentapi`）与子代理协同边界**：
   - **三层分工定位**：主线负责目标、排期、集成验收与面向用户的判断；临时子代理（`invoke_subagent` / `swarm`）承担有明确产物的短子任务，收证后立即 `kill`；独立「辅助对话线程」承担已配置的跨阶段持续职责、超大上下文物理隔离模块，或当前窗口异常受阻时的按授权换线程交接（长期辅助对话按原职责保留，不因单次子任务完成误关）。
   - **本机调用与授权红线**：通过 `~/.gemini/antigravity/daemon/hub_*.json` 核对存活 PID 取在线 Hub 的 `httpPort` 与 `csrfToken` 注入环境变量，调用 `language_server.exe agentapi`（`get-conversation-metadata` / `send-message` / `new-conversation`，详见 `tools-reference` 手册）。仅读写和联系**当前电脑上的反重力对话**（禁拿他端或跨机 ID 混调）；未经明确要求或换线程条件，日常拆分优先用内置子代理或既有辅助对话，**严禁擅自在客户端左侧刷屏新建可见对话**。通过 `send-message` 派活须记录目标 ID、预期里程碑与下一检查点；若需配置跨会话 `/automation` Sidecar，须经实跑录制最小权限白名单 `access_grants` 并交用户从 `sidecar://dashboard` 启用。
5. **贴近真实使用的最终验收、自包含 Reply 与 `%TEMP%` 安全收尾**：
   - 最终验收必须走正式入口、最终配置与真实状态链；末轮任何代码或样式修改后，**必须重跑对应测试并重新截取受影响的全部视角/页面（本地 HTML 复用会话须先 `close` 重开防缓存）**，严禁把改码前的旧截图混进「最终验证记录」。
   - 发送最终完工 Reply 前，回读 `plans/index.md`、正式报告、`Task.md`、`主人交流近况.md`、`memory_write` 记录及 `manage_task(Action="list")`（确认周期续接已清零），写出**不依赖上方任何中途进度气泡即可独立看懂全貌**的完整总结（含前置核验结论、核心实测结果、中途修正过的初算口径说明、产物链接与未决项）。
   - 清理临时文件遵守两道护栏：① 严禁让 `%TEMP%` 或会话 `scratch/` 承担唯一持久状态，清理前确认正式产物与证据已落入目标目录；② 只按明确路径归属清理本任务自建的可重建临时子目录，**严禁按时间/年龄批量清扫整个 `%TEMP%`**，防误删其它在跑对话、数据库或暂停态资源。
