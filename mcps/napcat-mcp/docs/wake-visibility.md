# 自动提醒的显示兼容

跟踪问题：[Issue #35](https://github.com/JuryBu/MCP-SKILL-RULES_packages/issues/35)。显示适配组件版本：`2026-09-19.1`。它独立于模型流式中转组件，不调整模型等待时间、重试或安全错误处理。

## 语义和问题

| 配置 | 空闲时开启一轮 | 运行中追加 |
|---|---|---|
| hidden | 首条可见 | 不增加用户消息气泡 |
| visible | 可见 | 每条可见 |

Desktop `26.915.4065.0` 的实时未知轮次初始化与历史加载不同：前者可能没有开头输入，后者会从历史第一条输入恢复它。因此同一批提醒可能在旧窗口可见，而新窗口重新加载后隐藏。仅省略 `clientUserMessageId` 不能保证实时视图行为；这不是服务端历史丢失，也不能据此认定账号或模型交付模式改变。

## 兼容边界

适配器在外层代理转发给 Desktop 时处理 v2 `item/started`、`item/completed` 用户消息通知。它只对预先登记的隐藏 wake 做精确文本摘要匹配，再绑定唯一线程、轮次和服务端消息 ID；不向模型改写或重发输入，不改请求响应，不改服务端历史和 ACK。

多个连接共享已经观察到的开头与消息身份，避免新连接把已知中途提醒误当开头。明确的客户端消息 ID、未登记文本、同文本但不同服务端消息、附件或文本注释、工具事件、错误和终止事件均原样通过。登记与轮次缓存有大小上限，不保存提示正文。

代理刚启动或缓存淘汰后，完全未知轮次的第一条观察消息保守放行，不猜测它是否为真实开头；客户端已有历史时仍按自己的历史视图处理。历史查询响应不筛除消息。旧协议和无法解析的大帧仍透明转发。隐藏表示显示偏好，不是机密性保证。

## 只准备，不切换生产

不同机器的外层代理可能保留不同的受管 App Server 生命周期实现。不要用仓库文件整份覆盖它们。准备脚本基于本机精确哈希和唯一代码锚点，只生成新的候选目录，保留其它实现；任何锚点缺失、重复、已经安装或源哈希变化均停止。

```powershell
$Source = '<本机安装目录>\src\codex-app-server-proxy.mjs'
$Expected = (Get-FileHash -LiteralPath $Source -Algorithm SHA256).Hash
$Output = Join-Path $env:TEMP 'wake-visibility-candidate-unique'
node ops/prepare-wake-visibility.mjs --source $Source --out $Output --expected-sha256 $Expected
```

输出包括候选代理、显示适配模块和两者大小/SHA256 清单；清单的 `productionModified=false` 明确表示尚未修改生产。输出目录必须不存在。之后在隔离副本中放置本机所需依赖，运行语法与针对性测试，并复核保留的本机生命周期方法。

## 启用与回退

启用前保存原代理字节、原有同名适配模块（如有）、文件哈希、运行进程身份和原启动参数。写入范围只允许 `src/codex-app-server-proxy.mjs` 和 `src/wake-visibility.mjs`，不包括 runner、模型中转、私有 binding、配置、认证、历史、任务账本或其它 MCP。

当前部分安装的外层 runner 在退出时会终止受管官方 App Server，因此不能把外层重启叫作无感热切。只有在明确的维护窗口、相关任务停稳且原启动/回滚入口验证后才能启用；不杀父进程试图绕过生命周期约束，也不抢其它维护租约。

失败时以原启动参数恢复原代理文件及原适配模块，新增模块可移至本次备份目录，不删除其它文件。验证外层、官方 App Server、工具与路由恢复后才结束维护，清除的只能是本次拥有的维护标记。

## 验收与当前状态

自动检查覆盖单元行为、两个真实 WebSocket 连接、原代理回归、源文件哈希与选择性准备。对实际安装 renderer 的独立函数检查能验证气泡投影，但不等于真实 Desktop 的完整验收。

生产验收还必须检查：运行 `/status` 出现本组件 `wakeVisibility.version`；正常业务中首条可见、中途 hidden 不增加气泡、visible 可见；新旧窗口和历史重开一致；模型收到通知且任务可精确 ACK；人工消息、工具与取消不受影响。不能只凭代码哈希或测试通过声明完成。公开跟踪在两机实际 UI 验收前保持打开。
