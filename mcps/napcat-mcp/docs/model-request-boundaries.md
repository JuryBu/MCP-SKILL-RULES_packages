# 模型请求体与流式边界

## 适用范围

模型中转版本 `2026-09-27.1` 将默认传输体积上限从 64 MiB 提高到 128 MiB，解压体积上限从 96 MiB 提高到 192 MiB。普通聊天请求确定性超限时，向客户端返回一次可理解的终止消息，避免原生 App Server 反复上传同一个超限请求。传输体积与解压体积分开检查、编码校验和解析隔离沿用已有实现，不删除图片、不修改请求内容、不截断上下文。

这是模型 HTTP 中转的变更，不改变 AppServer 的消息隐藏规则，不恢复已暂停的任务，不清理任何对话历史，也不自动改账号、系统代理或项目配置。

## 有界接纳

| 范围 | 默认值 | 行为 |
|---|---|---|
| 编码后的单个请求 | 128 MiB | 普通聊天超限返回一次终止消息，上下文压缩请求保留 JSON 413 |
| 解压后的请求与中间层 | 192 MiB | 普通聊天超限返回一次终止消息，上下文压缩请求保留 JSON 413 |
| 所有在途编码体预算 | 256 MiB | 用完返回 503 与 `Retry-After: 1` |
| 解析执行 | 一个 worker，最多 16 个等待项 | 等待与执行共用 15 秒期限 |

因此，编码后不超过 128 MiB、解压后不超过 192 MiB 的合法大请求可以通过。上述预算不是进程总内存上限；网络缓冲、worker structured clone、解压结果、JSON 字符串和对象也占内存。worker 的 384 MiB V8 老生代限制不约束所有外部 Buffer，不能把它当成进程 RSS 保证。解析结束或取消后退出 worker，避免长期保留大解析堆。共享在途编码体预算仍为 256 MiB，不因单请求门槛提高而取消并发保护。

支持 `identity`、`gzip`、`deflate`、`br`、`zstd`，复合编码按逆序解码，每层都检查解压限制。编码列表最多 16 层、256 字符。zstd 在交给原生解压器前校验帧结构完整性，兼容拼接帧、可跳过帧和校验和；防止当前运行时把截断流的部分输出误认为完整 JSON。

环境参数 `CODEX_MODEL_STREAM_PROXY_MAX_DECODED_REQUEST_BYTES` 与 `CODEX_MODEL_STREAM_PROXY_MAX_TOTAL_REQUEST_BYTES` 由 runner 读取；不会自动改已有环境配置。前者允许上限 256 MiB，后者 512 MiB，调高前必须重新评估真实资源与并发，不能用于绕过保护。

## 错误与观测

无效 JSON、非对象 JSON、压缩损坏分别返回可区分的 400；未知内容编码返回 415；普通聊天体积超限记录 413 原因后返回一次终止完成事件，避免原生 App Server 对 413 自动重试。上下文压缩请求需要真实的压缩结果，超限时保留 JSON 413 错误，不能把普通助手提示冒充成功的压缩结果；该路径沿用客户端原有错误处理，本次未宣称其原生重试次数已改变。解析排队、超时或 worker 失败返回 503 并保留重试属性。拒绝发生在发往上游之前，不生成虚构的模型身份，也不计作已发送的模型请求。日志只记录有限的原因、阶段和字节数，不记录请求正文、图片或凭据。

客户端取消时中止对应的排队或解析工作，等待 worker 真实退出后释放执行位；在解析返回后再次检查取消状态，不能让已取消的大请求继续发往上游。

## 已有保护与计时边界

| 现象 | 修正 |
|---|---|
| 请求超限先断 socket，客户端拿不到 413 | 先发送可读的错误响应，再关闭连接 |
| 多个合法 SSE 帧一起到达，合计超过单帧额度便被拒绝 | 按每个消息帧和未完成帧检查，完整/未完成的超大单帧仍拒绝 |
| 上游 403 错误正文超限，被误归为可重试失败 | 正文不可读时仍按 HTTP 状态分类；429/503 保留重试属性 |

40 秒首进度、40 秒进度空闲、300 秒自适应等待和 90 秒上游空闲策略不因这次体积修复统一放宽。计时仍从每次上游尝试建立并开始发送前启动，因此包含上传和等待首个有效内容；`ClientRequest` 的 `finish` 只记录“请求体已交给本机操作系统”的交接点，不代表远端已经收完，不能把它当成精确的服务器收包时间。启动队列和解压保护也保留。

## 验证方式

普通测试可运行 `node --test --test-concurrency=1 test/request-body-inspector.test.mjs test/request-body-proxy.test.mjs test/limit-regressions.test.mjs`。其余模型流、自适应和工具完成保护按受影响路径验证；本机已有额外集成时，另核对其兼容性与来源。

大图测试默认不随普通测试分配大量内存。显式设置 `RUN_LARGE_REQUEST_TESTS=1`，用 Node 24.19 的 `--expose-gc --test --test-concurrency=1 test/large-image-http.test.mjs` 运行，建议为独立测试进程树预留约 1.5 GiB 硬预算。`LARGE_FIXTURE_ENCODING=gzip|zstd` 选择压缩格式；可用 `BASELINE_MODEL_PROXY_FILE` 指定独立旧版模块，做相同请求的前后对照。

夹具由随机像素生成 32 张有效 PNG，仅访问环回假上游，校验传输原字节及解压内容 SHA-256；覆盖超过旧 64 MiB wire 门槛的合法请求、重复、双请求并发、取消后继续使用、配置化 96 MiB 边界和超出一个字节。测试不读取真实用户图片、不消耗模型额度，隔离通过不代表生产已经安装或真实账号请求已恢复。

发布应冻结源码与哈希，先演练实际启动、正常停止、文件恢复与旧版重新启动，再协调共享模型服务的空闲窗口。只安装本次已验证范围，保留其它已部署集成；生产切换后分别确认运行版本、文件身份和正常模型响应。隔离演练不代替真实切换后的验收。
