# 模型请求代理的组件更新

本入口只负责内层模型请求代理，不安装外层 AppServer 适配，不停止 Codex、其它服务或科学计算。正式操作仍须满足已有维护授权和实际请求空闲窗口；隔离验证不占用生产端口或生产状态。

## 两台机器使用同一源码

公共入口为 `ops/maintain-codex-model-stream-proxy.ps1`，恢复助手为同目录的 `model-proxy-recovery-intent.ps1`。两台机器使用同一提交、同一字节的入口与助手，不在接收端替换硬编码版本、文件数量或容量。

候选目录包含发布文件和 `release.json`。发布清单样例为 `ops/model-proxy-release.json`，声明候选版本、允许替换的文件及容量。准备时将发布清单、入口、助手、候选文件和本机实际旧版固定到本机恢复计划，之后变化会被拒绝。机器差异只通过代码目录、候选目录、状态目录、独立备份目录、端口和 Node 路径传入。

本机恢复计划、DPAPI 密钥、维护租约、账号、配置和运行日志不随公共包传输。接收端生成自己的备份与恢复状态，保留自己的私有适配。

## 操作与结果

| 操作 | 行为 |
|---|---|
| `Prepare` | 备份目标与权限，记录实际旧实例、发布清单和依赖身份，不停服务 |
| `Inspect` | 只读核对准备材料和当前实例，不写事务锁、租约或替换意图 |
| `Apply` | 最后核对空闲并正常停止内层，成功停止后才建立替换意图，替换并验证候选 |
| `Rollback` | 使用本机签名计划和原备份独立恢复；不依赖原父进程或候选发布清单 |

请求仍在运行或最后一次停止检查拒绝时，服务不停止，也不生成替换意图或暂存文件，因此同一准备材料在真正空闲后仍可使用。成功停止后发生准备、替换或启动错误，则保留原错误并执行同范围恢复，不能以恢复旧版报告升级成功。

切换完成须核对实际版本、文件身份、正常模型/工具请求、原状态与保护项。操作器退出、终端没有输出、文件已传输和健康接口有进程，分别只说明各自阶段，不代替完整结果。

## 不让终端等待后台服务退出

不能用 `$output = & child-PowerShell ... 2>&1` 捕获会启动长期 Node 服务的安装子进程，也不能使用会等待整个后代进程树的 `Start-Process -Wait`。后台 Node 可能继承输出句柄，使安装器已退出但前台永远等不到 EOF。只给 Node 设置输出重定向不足以修复已经复现的链路。

调用入口应将安装 PowerShell 的输出和错误写到独立文件，等待其精确 PID 和实际退出码，并有明确上限。等待到期后记录结果未知，先检查原事务日志和实际服务，不重发安装，不强杀服务或整个进程树。人工入口与自动入口必须使用同一已验证调用方式。

公共调用器是 `ops/invoke-maintenance-powershell.ps1`，它为精确子进程保留 `stage-result.json`、`launcher.log` 和独立 `child.log`，以实际退出码返回；到期返回 124、状态 `unknown`，不杀进程、不重试。调用器必须作为独立 PowerShell 进程使用，不能在长期维护脚本内直接点加载或调用后期待继续执行，因为它会退出该 PowerShell 进程。

输入 JSON 只传操作参数，不是新的授权文件。先把本机已核实的目录、端口、Node 路径及 `Action` 写到自有参数文件，再通过相同 PowerShell 版本的独立进程调用。操作者须传入已核对的操作器 SHA；准备、检查、切换和恢复分别记录独立阶段，不根据启动成功推断安装成功。内层切换阶段应显式给足正常停止及启动的预算，例如 120000 毫秒，不能机械套用调用器对短阶段的默认 30000 毫秒。

## 接收端工作与时间控制

接收端负责本机合法执行、必要适配、验证和最终证据；开发端检查里程碑及最终源码/运行结果，不逐函数审批。候选、脚本、错误停止、恢复和输出结束行为应在叫用户回来之前，通过同版 PowerShell、同卷文件和真实入口的自有 TEMP 环回验证，不等用户守着终端时继续修准备脚本。

每次同步记录本机准备开始/完成、候选送达、对端业务接受、隔离完成、实际安装和正常使用时间。到双方约定的耗时边界必须调整关键路径，停止没有新证据的重复检查；环境调查只查真实错误所需的差异，不做全面系统审计。新增准备问题不无限延长用户等待，也不要求生产为只读调查留空。

原生命令工具的 `blocked by policy`、Windows PowerShell 的 `UnauthorizedAccess`、WMI 参数错误和实际服务忙碌是不同阶段的失败，应保留原命令、参数和错误来源。工具策略拒绝不通过拆命令、替换工具、提权或修改策略重试；完整访问界面本身不能证明某条命令的执行规则已经允许。合法执行路径未确认时明确报告该边界，不让用户承担无限试错。

## 定向回归

`test/fixtures/model-proxy-component-maintenance.ps1` 使用实际安装的启动/停止入口和自有 TEMP 状态、端口、受控环回上游，覆盖真实 Busy 后空闲再次安装、最后停止拒绝、停止后意图写入失败、候选启动后失败及发布清单变化。显式传入 `NodePath` 选择目标实际二进制，传入 `InvocationPath` 则经公共调用器完成真正的独立 Prepare/Inspect/Apply/Rollback，而非在同一进程伪造入口函数。夹具只修改 TEMP 中的合成候选版本，不重放真实图片或调用付费模型；所有自有进程正常收尾。每台机器使用同一源码并记录真实 PowerShell 版本、入口哈希、原始日志、字节/权限和正常业务结果。

`node --test --test-concurrency=1 test/maintenance-powershell-process.test.mjs` 覆盖实际 WinPS5/PS7 的有限后台 Node、真实非零退出、空输出、字面 JSON 参数、解析失败及超时自然退出。需要指定便携 PS7 时使用 `MAINTENANCE_TEST_PWSH`，不修改系统安装或永久执行策略；没有该版本时如实保留未测边界，不把跳过算通过。
