# 7.3.3：跳转期间读取页面

本次升级修复正文和 HTML 抓取在网页跳转期间遇到旧执行上下文被销毁而提前失败的情况，适用于 Antigravity、Codex、Claude Code 和 Windsurf 共用的 MCP 服务。工具名、输入字段、图片返回方式与模型路由保持兼容。

## 正常使用

继续按原方式调用 `web_fetch_page`、`web_fetch_html`。服务沿浏览器真实跳转读取最终文档，覆盖 HTTP 重定向和脚本导航，保留页面关闭、请求取消和原总期限。无需猜测或手工改写网站的完整目标地址。

只读采样最多恢复两次，恢复会重取当前文档和 HTML 选择器，文档变化后重新计算稳定状态。稳定页面直接读取；截图保留图片、字体、懒加载和长页面覆盖检查。达到检查期限时，已有视觉 `partial` 和未完成资源说明继续返回。

`timeout` 继续表示原页面加载等待，工具请求的总期限沿原并发管理规则执行。导航恢复不会延长该总期限。点击、输入、提交和用户指定的任意脚本继续只执行原请求，不因读取恢复自动重放。

## 故障说明

读取失败结果仍使用 `isError=true`，原文本错误保留原因，同时新增 `_meta.webFetcherReadFailure`：

| 字段 | 含义 |
| --- | --- |
| `code` / `phase` | 失败类别与读取阶段 |
| `requestedUrl` / `finalUrl` | 原目标和实际停留地址 |
| `retries` | 本次读取已执行的导航恢复次数 |
| `cause` | 原始错误或明确的读取期限原因 |

例如 `phase="html.selector"` 指在最终元素 HTML 读取时失败，`phase="readiness.content.sample"` 指内容就绪采样。先按实际阶段和最终地址核对，不必反复增加等待或要求重新登录。

挑战、登录和访问拒绝仍由 `pageAccess` 描述。`humanAssistance="never"` 不创建人工窗口；允许人工辅助时仍沿现有后台任务和十分钟操作窗口处理，不把验证页当作可读正文。

## 验证入口

`npm run test:navigation` 检查恢复边界、期限、取消、关闭和诊断。真实浏览器测试需先构建，并显式设置 `WEB_FETCHER_BROWSER_TESTS=1`；随后运行 `npm run test:navigation:browser`，使用本地 HTTP、无头 Edge 和标准 MCP 调用检查真实导航，未启用时明确跳过。旧链路使用 `npm test`，图片、就绪与人工验证分别沿现有浏览器测试入口验证。

安装只涉及 web-fetcher 组件。保留旧进程和现有登录资料，文件安装完成、进程加载新版与真实业务验收分别记录；共享 broker 或其它 MCP 无需随本次修复整体重启。
