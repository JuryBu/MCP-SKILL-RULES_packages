# 7.2 升级说明

> 本说明描述 7.2 行为与部署注意事项，不表示任何宿主、机器或生产安装已经更新。应分别核对代码版本、部署文件和真实工具调用。

## 页面与请求接纳

Windows 默认页面容量目标由 5 提至 8，但只有实时物理内存、提交内存和采样新鲜度都满足条件时才会发放页面名额。显式设置的既有 `WEB_FETCHER_MAX_CONCURRENT_PAGES` 优先于默认值。接纳使用有界队列，并按 `ownerId` 轮转选择，避免一个调用方长期占住名额；排队、取消、超时和资源不足会返回明确的接纳结果。

非 Windows 没有完整的系统内存采样，继续采用保守的 5 页上限。即使在 Windows，8 也是资源允许时的容量目标，不是同时打开 8 页的保证。

`web_interact` 与 `web_pipeline` 复用 `sessionId` 时按实际 Page 串行，不同 alias 指向同一 Page 也不会交错操作。`web_inspect` 仍要求 URL，不支持把 sessionId 当 URL 替代；直接 `desktop_*` 操作也不应与同窗口的网页 alias 并发，需调用方串行安排。关闭、取消、状态查询走独立控制/轮询通道，实际关闭仍等待在途页面操作安全结束。

普通按钮点击若已确认不会下载或开新窗口，可显式用 `web_interact(waitForEvents=false)`，或在 pipeline 的 click 步骤设置 `waitForEvents:false`，跳过旧逻辑的事件探测等待。省略或传 true 保留旧下载/弹窗收集行为。快速返回不保证异步业务状态已更新，需要时追加 wait；截图仍独立等待视觉资源，不因快速点击而降低截图就绪要求。

## 可选响应式 viewport

`web_fetch_page`、`web_fetch_screenshot`、`web_fetch_rich`、`web_interact`、`web_pipeline` 和 `web_inspect` 可传：

```text
viewport: { width: 240..4096, height: 240..4096 }
```

宽和高必须为整数，面积不超过 8,388,608 CSS 像素。省略时保持原默认尺寸或已有 session 的尺寸；只有显式传入时才调整已有 session。

`viewport` 只改变网页的 CSS 布局宽高，不模拟设备 User-Agent、DPR 或触摸能力。它也不同于 `fullPage`（截图覆盖的滚动范围）和 `scale`（文档/截图输出的放大倍率）。PDF、Office、EPUB、媒体及 native 窗口不改尺寸；对文件预览传入 `viewport` 会明确拒绝，而不是悄悄套用网页尺寸。

## 就绪、图片与人工登录

视觉就绪会检查图片、背景、poster、字体、同域 iframe、布局与全页懒加载。时间或扫描上限到达、跨域 frame 不可检查、资源仍未完成等情形会返回 `partial`/不完整信息，而不是把重资源页面误称为完全就绪；调用方应查看对应的未检查原因，再决定缩小范围或重试。

图片仍默认以 MCP `image` 内容返回。需要兼容临时路径的自动化调用必须显式传 `saveMode="file"`。人工登录与用户辅助验证保持最长 600 秒的可操作窗口；保存 Cookie 或 localStorage 仍不等于站点认证已经成功，需实际访问目标页面确认。

## 检查结果的正确用法

检查报告中的 `confidence` 表示证据强弱，`candidate` 是待人工判断的候选，不应直接当成缺陷结论。`limitations`、`detectionTruncated` 与截图预算提示说明未检查或未附图的范围；达到预算时报告会保留并明确缺口，不会静默丢弃。请据此缩小页码、检查范围或改用 `saveMode="file"` 获取路径型输出。

少量真实页面样本只说明这些场景已被测到；它们不构成通用性能提升比例、p95 指标或所有站点的承诺。

## 发布前核对

基础回归与定向验证分开运行，浏览器测试需要已安装的 Edge，Python 检查测试需要 python-pptx 与 PyMuPDF：

PDF 检查优先使用官方推荐的 `pymupdf` 导入名，兼容仅提供旧 `fitz` 名称的版本；不再让 PyMuPDF 1.28.2 的旧别名弃用提示污染 JSON 输出。已对 1.26.4 与 1.28.2 执行 PDF 25项及真实 HTTP 检查回归。指定解释器用 `WEB_FETCHER_PYTHON`，部署机缺依赖时必须明确标注该能力不可用，临时测试环境通过不代表生产依赖已安装。

```text
npm test
npm run test:inspection:python
npm run test:inspection:http
npm run test:viewport
npm run test:contract
```

`npm test` 覆盖图片交付、登录生命周期、资源接纳、请求/会话并发、视口参数和检查资产一致性；Windows 真实采样测试需设置 `WEB_FETCHER_TEST_MEMORY_SAMPLER=1`。部署前还需运行真实网页就绪和共享 HTTP 并发测试，具体环境与结果应记录在发布清单。部署产物必须包含检查所需的 Python helper 及同目录依赖、Windows native PowerShell helper；缺少任一 helper 时，不应宣称相应检查/采样能力已部署。

模型链（含 `modelChain` 与兼容 `chain`）和四宿主的接入接口没有变化；普通抓取、截图、交互、下载与登录路径不因模型链选择而改变。
