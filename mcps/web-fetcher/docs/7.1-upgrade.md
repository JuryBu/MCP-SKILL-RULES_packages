# 7.1 compatibility and verification

## Changes

Screenshot-bearing tools now return standard MCP text/image content by default. Explicit `saveMode: "file"` retains legacy paths and report screenshot fields. Multiple pages and tiles retain order, with a ten-image / 12 MiB base64 limit; a partial capture or exceeded limit is not reported as complete success.

Manual login and user-assisted verification share one lifecycle: a 600-second user window, serialized periodic storage capture, save-before-timeout-close, and bounded recovery after an owned Chrome exits. Capture counts, durable save evidence, errors and actual website access are separate. LocalStorage-only sites do not require a nonzero Cookie count. Recovery does not open or delete an external user's profile.

Shared authentication updates use per-key conflict checks. An old context cannot overwrite newer shared Cookie/localStorage values. Restore is origin-scoped; a storage revision prevents repeating an old restore on every reload and undoing a site's token refresh. Failed export preserves the profile with a recovery marker, including across later orphan cleanup.

## Compatibility boundaries

The protocol is independent of Antigravity, Codex, Claude Code and Windsurf. Existing endpoint mounting and model-provider selection are unchanged. Standard HTTP and stdio checks prove the server-side contract; they do not claim that every host's current UI was manually viewed. Hosts control image display limits. Integrations that parse old path responses must explicitly select file mode.

The login window remains visible in normal use. Tests can explicitly request an internal headless launch; this is not a public login-tool parameter and does not change the user's interactive login behavior.

## Repeatable checks

| Command | Scope |
|---|---|
| `npm test` | Build, image contract, storage and lifecycle unit regressions |
| `npm run test:images:http` | Isolated Edge, real HTTP MCP, screenshots, interactions, PDF pages, CDP |
| `WEB_FETCHER_LIVE_LOGIN_TEST=1` with `npm run test:images:http` | Adds headless synthetic manual-close recovery, background polling and authenticated-page reaccess |
| `WEB_FETCHER_LIVE_LOGIN_TEST=1` with `npm run test:login:browser` | Owned/borrowed browser lifecycle, write failure and recovery; some explicit human-window fixtures may be visible |
| `WEB_FETCHER_600S_TEST=1` with `npm run test:login:600s` | Real ten-minute wait and a late synthetic credential update, without real accounts |

Set the environment variable using the syntax of the current shell. Browser tests use temporary roots and must clean only their own processes and data. A user interruption or browser exit before the deadline is not a passing timeout test.

## Component deployment

Validate a candidate before touching production. Back up the component's program files and record source/build hashes. Preserve local configuration, profile paths, all authentication data, dependencies not changed by this release, and other MCPs. Only reload the web-fetcher backend after checking outstanding calls and owned browser sessions; do not restart the global broker just to update this component.

Check the actual post-reload process and call tools through the installed HTTP endpoint. Retain rollback files until both installations are verified. A repository commit, a compiled directory or a transferred archive alone does not prove an installed backend was upgraded.
