# 7.3.1 登录结束后的存储恢复

本次更新针对 `web_login_browser`、UAV 和自有 human browser 的 Cookie/localStorage 保存。原工具参数、600 秒人工窗口、网页与本地文档功能、四宿主接入和模型选择保持原有接口。

## 使用方式

以 `web_login_browser(startUrl="https://example.test", background=true)` 启动专用登录窗口，用返回的同一 `taskId`、`waitSeconds=30–45` 查询。完成操作后可以关闭窗口，后台会继续进行有界的最终恢复和退出确认。若窗口停在空白页，在该专用窗口打开本次 `startUrl` 即可继续。

返回中的「会话期间已写入」是周期采样的保存记录，「最终 Cookie」和各个来源的 localStorage 状态说明最后一次读取或写入。`empty` 表示成功读取后没有符合保存条件的条目，`capture-failed`、`persist-failed` 和 `pending` 分别对应读取失败、写入失败和待确认。失败项保留来源地址、阶段与错误分类，输出省略存储值、页面路径和查询参数。

保存后继续访问目标页面，核对实际账号和页面内容。遇到警告，先查看具体失败来源及保留的恢复目录；已有登录可用时可继续使用，排查时复用保留资料。

## 恢复如何保护原资料

采样器在打开目标页前监听主页面、跳转和新窗口，保留已访问的 HTTP(S) origin（协议、主机与端口）。关窗后先验证本进程所有权、原 Chrome 退出、目录与可执行文件身份，再只读复制原 profile。

恢复仅在独占临时副本运行。副本排除标签恢复记录、Service Worker 和浏览器缓存，保留 `Local State`、Cookie 数据库、localStorage 等网站资料；session 恢复参数用于加载随浏览器会话保留的 Cookie。进程启动即通过本次持有的拒绝代理，并禁止 DNS 访问；连接后默认拒绝请求，仅允许专用空白页的当前来源主文档读取，绕开 Service Worker。

恢复按 30 秒预算调度，按来源分配剩余时间。复制按 1 MiB 分块检查剩余预算，操作系统本身的磁盘阻塞仍可能延长返回时间。副本最多复制 512 MiB，并预留磁盘空间，链接或特殊文件、容量不足、复制超时会停止恢复并保留原件。来源最多 64 个；跨源 iframe、超限或监听不完整会明确报告覆盖待确认。导出范围保持为 Cookie/localStorage，IndexedDB 等其它存储不写入共享备份。

保存采用原会话基线比较：另一会话已经写入的新值会受到保护。读取失败、删除语义待确认、较新备份冲突、来源未覆盖或恢复进程未退出时，原 profile 持续保留。原 Chrome 异常退出时会尝试读取已落盘的资料，同时报告 `original-browser-abnormal-exit` 并保留原件，最终 Cookie 可能尚未来得及写入磁盘。恢复副本只在其进程退出确认后清理，失败结果会给出残留副本位置。

## 验证入口

普通回归运行 `npm test`，其中包含来源状态、并发写入、失败脱敏及迟到读取测试。

真实隔离 Chrome 测试：在 PowerShell 设置 `$env:WEB_FETCHER_RECOVERY_TEST='1'`，再运行 `node --import tsx --test --test-concurrency=1 tests/login-recovery-browser.test.mjs`。测试仅使用合成账号、临时 profile 和无头进程，检查立即关窗、session-only Cookie、多来源、慢站/离线、Service Worker 重放和原件字节保持。

真实十分钟测试：设置 `$env:WEB_FETCHER_600S_TEST='1'`，运行 `npm run test:login:600s`，在到期前写入最终合成凭据，再验证关闭后的保存与恢复页面。上述环境变量只用于测试，不修改人工操作期限。
