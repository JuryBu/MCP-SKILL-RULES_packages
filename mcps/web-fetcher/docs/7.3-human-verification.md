# 7.3 人工验证与同页续接

## 修复目标

此前人工验证可能占用一次同步 MCP 调用长达十分钟，超过客户端或 broker 的单次期限。另有失败分支在同域已尝试验证、或者人工未完成时直接返回挑战页，导致截图/正文工具报告完成。7.3将页面访问状态、人工任务状态与存储保存状态分开，强挑战先返回错误和可操作的下一步，不缓存挑战内容，不把它提交给 AI 摘要。

这是普通 MCP 工具扩展，仍使用 `tools/call` 的 `content`、`isError` 和可选 `structuredContent`。不依赖客户端专有事件或额外 MCP Tasks 协议；Antigravity、Codex、Claude Code、Windsurf 使用相同工具契约。宿主实际展示和连接状态仍应分别验证。

## 自动触发与禁止开窗

网页工具新增可选 `humanAssistance="auto"|"never"`，默认 `auto`。发现强人机验证时，明确、稳定且非 `global` 的 `ownerId` 可以创建后台人工任务；缺少归属时仍报告挑战，但不启动无法归属的共享窗口。普通短页、合法空白页不会仅因文字不足而弹窗，存在业务正文的安全脚本也不能单独证明阻断。

`never` 只返回阻断状态，适用于无人值守测试。只在用户准备好时再显式调用 `web_human_verification(action="start")`。自动任务按 owner 与目标去重，失败后有短暂冷却；显式 start 可重新尝试，不存在全进程永久禁用某域名的状态。

结果示例（ID仅为占位符）：

```json
{
  "isError": true,
  "structuredContent": {
    "pageAccess": {
      "status": "challenge_required",
      "blocked": true,
      "contentConfirmed": false,
      "taskId": "human-verification-...",
      "ownerId": "project-a",
      "nextAction": "使用web_human_verification查询任务；完成后用sessionId继续只读工具"
    }
  }
}
```

访问状态包括 `content_ready`、`challenge_required`、`login_required`、`loading`、`access_denied`、`unknown`。`unknown` 不是成功认证；人工续接必须在指定目标页面发现内容，提供 `waitFor` 时还必须匹配该正文选择器。正常页面的旧返回格式不强制包装这些字段。

## 十分钟人工窗口

```text
web_fetch_rich(url="https://example.com/private", ownerId="project-a", humanAssistance="auto")
web_human_verification(action="status", taskId="human-verification-...", ownerId="project-a", waitSeconds=30)
```

`start` 在建立任务后短返回。排队与浏览器启动有独立期限，窗口实际就绪后才开始600秒人工租期；租期包含 `ready` 后继续读取的时间，不会被一次查询重新延长。`status` 默认立即返回缓存的任务状态，最多等待45秒，不为每次轮询重复导出浏览器存储。

任务的 `metadata.phase` 描述 `queued/opening/awaiting_user/ready/failed/expired/cancelled` 等阶段，独立于后台任务的 `running/cancelling/done/error/cancelled`。`ready` 时租约仍运行以保证到期自动清理。`storageSaved` 只说明存在存储写入记录，不能替代 `contentVerified`；Cookie数量为零也不自动表示未登录。

保留人工窗口直到读取结束。用户直接关窗后会尽力保存状态，但原页面已不存在，任务不能报告可同页续接，也不会自动重放原动作。进程重启会使旧任务ID失效，结果会提示 `task_not_found` 和当前代次；不自动重新创建任务或重放操作。

## 复用验证完成的同一页面

在 `metadata.phase="ready"` 后，使用返回的 `sessionId` 和相同 `ownerId`：

```text
web_fetch_page(sessionId="session_...", ownerId="project-a", outputMode="full")
web_fetch_screenshot(sessionId="session_...", ownerId="project-a", viewport={width:390,height:844})
web_fetch_rich(sessionId="session_...", ownerId="project-a")
web_human_verification(action="close", taskId="human-verification-...", ownerId="project-a")
```

三个工具都可只传 `sessionId`，不会重新导航或关闭借用页面，不使用 URL 缓存。若同时传 `url`，必须与当前目标一致。`sessionId` 路线仅用于 HTTP/HTTPS renderer，不把 Office/PDF/EPUB 文件转换路径伪装成原页面。原来的 URL、本地文件、视口、图片 inline/file 和模型链参数保持兼容。

已经存在的人工浏览器也可通过 `start(humanSessionId=..., pageId=...)` 接入，同样要求明确owner。多窗口应指定 `pageId`，不能猜测用户正在操作哪个窗口。去重同时比较目标、人工浏览器、页面与 `waitFor`；同一页面仍有活动任务但条件不同会明确报冲突，不会把另一组条件的完成状态返回给当前调用。

只读续接由调用方显式发起，不自动重放点击、输入、脚本、下载或 pipeline。人工验证页再次被阻断时不会自动创建另一窗口；pipeline中途遇到挑战会阻止后续步骤。后台验证与前台操作对同一 Page 串行，避免状态探测与脚本交叉。

`close/cancel`短返回清理中的状态，可继续短轮询直到 `cleanupStatus="done"`。只关闭该任务新建的浏览器；传入已有 `humanSessionId` 时只释放本任务新建的页面别名，保留原人工浏览器、页面和原有别名，无论该浏览器原本由谁启动。清理异常或期限到达但退出未确认时明确报错，不能把已发关闭命令当成已关闭。`cleanupStatus="failed"` 时对同一task再次 `close` 只重试清理，不重跑验证或打开新窗口。普通 `web_login_browser` 和底层 Human Browser 工具继续保留。

## 回归与发布

`npm test` 包含新增访问状态、后台生命周期和借用读取测试。`npm run test:contract` 检查真实 stdio 服务的33个工具及资源说明。真实无界面 Edge/HTTP 用例需要先构建，再设置 `WEB_FETCHER_BROWSER_TESTS=1` 执行 `npm run test:verification:browser`。额外设置 `WEB_FETCHER_ASSISTANCE_600S_TEST=1` 会实际等待新人工任务的600秒到期；旧 `WEB_FETCHER_600S_TEST` 对应旧登录流程，不可互换。

拟真测试使用临时 profile 与本地站点，覆盖仅复制 Cookie 无效、同页面 sessionStorage 仍有效的场景，不声称模拟了 Cloudflare 的内部算法。真实受保护网站必须另外验收，挑战失败、权限不足和未登录不可记为抓取成功。通用协议测试不冒充四宿主界面逐一实测。

发布仅更新 web-fetcher，保持认证备份、私有路径和其它 MCP 不变。切换前检查在途调用与持久人工任务，准备可独立执行的组件回退；磁盘版本、已加载版本、公开提交和训练机安装分别确认。不得为本组件重启全局 broker。
