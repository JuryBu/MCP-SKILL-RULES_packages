# 自动摘要当前性与失败来源

记忆正文、调用方填写的`searchSummary`和自动生成的`autoSummary`分别保存。正文更新成功后，自动摘要可能仍在生成或生成失败；原有摘要及其`summarySource`保留，供查回旧版本来源。

普通搜索、批量搜索、模糊降级和相似检查会排除最新生成失败、正在生成以及来源指纹已变化的自动摘要。来源未核的旧格式摘要继续作为候选线索，结果、读取和导出会提示按正文核对；其状态仍为`unverified`，补缺继续跳过。来源一致的摘要状态为`current`。正文搜索材料先去掉frontmatter，标题、标签、手写搜索说明和当前正文继续可查，原摘要与来源记录保留。

显式`memory_stats(action="enhance")`检查当前性，旧摘要字段非空仍会判断是否需要补缺。缺少可核来源的旧格式摘要保留为待核项，使用明确选择的定点修复处理，避免一次全局补缺重生大量旧摘要。正在生成、取消、安全停止或`UnknownOutcome`先保留原调用状态，避免重复执行。读取、查询和状态提示不会自动触发摘要生成，也不会改写旧文件。

搜索先用索引中的状态排除失败和正在生成的摘要；来源缺失的旧摘要保留为带提示的线索，只有需要核验的成功摘要才按文件身份检查来源，并复用有界结果缓存。核验读取预算为128KiB，超出时保留原摘要并标为待核线索。正文片段增量跳过frontmatter后计3000字符，元数据预算64KiB，避免长失败说明挤掉全部正文。已知工作区直接传递来源hash，不逐条跨库反查。

新的Grok可用性失败会在`autoSummaryProvenance.grokAvailabilityDiagnostics`保留本次检查的阶段、HTTP状态或安全错误码、原检查时间、耗时、超时预算与`cacheHit`。缓存命中保留原检查身份；并发检查分别回传诊断。该字段不保存凭据、地址、HTTP响应正文，也不增加健康探针、重试或模型请求。

历史失败缺少诊断时继续保留已知事实，不能从通用不可用提示推断具体登录或网络原因。原始记忆不因本次升级自动重新生成；定点修复沿用[摘要修复流程](auto-summary-repair.md)。
