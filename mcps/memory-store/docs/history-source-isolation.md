# 历史读取的故障隔离

1.27.2保留五端搜索、范围准备、既有缓存及引用协议，修复WSF递归查询的连接顺序、定位探针的读取范围，以及重读取阻塞共享服务的问题。调用者仍须明确选择数据端，并区分调用者`conversationId`和目标`conversationIds`，原有参数与任务恢复入口不变。

## 重计算与控制请求

默认对话定位整段在独立子进程执行；WSF SQLite发现、身份解析、指纹和正文转换，以及Claude Code、WSF、Antigravity、DSH的新语料读取、列举和缓存投影，使用相同的受控源执行器。Codex既有流式读取和渐进准备/完整fetch的Worker继续保留。显式注入自定义测试backend或回调的开发接口仍由调用方负责执行环境。

源执行器默认同时运行2个作业，Node堆上限每个512MiB，分别可用`MEMORY_STORE_SOURCE_WORKERS`和`MEMORY_STORE_SOURCE_WORKER_HEAP_MB`配置；堆上限与进程树实际提交内存分别统计。IPC按有界块传送并处理发送背压，避免一次向主进程交付整个原始历史对象。已验证的Devin身份提示在作业之间保留，复用时仍按原来源核验逻辑检查。

显式读取期限包含进入源执行器前的工具排队与源队列等待；后台任务沿自己的生命周期执行。源作业在超时、取消或服务正常退出时停止自有进程树，确认退出后才结束这项读取。范围准备、全库搜索和后台任务的状态/取消走独立控制通路，长轮询不占用普通查询和取消的执行名额。

定位的预算不足、来源不完整和未扫描范围仍通过`partial`、覆盖说明及候选警告返回。没有读完的来源继续保留未核实状态；固定引用、完整来源和相对轮次的原有含义不变。

## 未知目标的定位与部分返回

`list`可以只提供明确的`dataChain`、工作区和`contextProbe`，先寻找目标身份；当前调用者的`conversationId`只用于归属，不会作为待找目标。显式选择数据端、没有查询词的普通列表也走有预算的本地元数据入口，Antigravity本地PB存在时可直接枚举，来源状态会列出实际可用性。

`contextProbe`用于定位已经出现过的一段正文，允许同一段文字在引用时改变标点、空白或段落，命中返回来源中的原文片段。匹配仍要求整段文字连续对应，词语改写、缺词或增词需要换用真实原话或显式模糊深搜。`deep_locate(mode="exact")`继续按原来的精确规则匹配。

各来源独立开始枚举与正文核验，已就绪来源无需等待其它来源枚举结束。完整核验的候选通过分块检查点传回；到期时返回已经收到的完整候选、数据源状态和`partial`说明，未封口的传输块不会进入命中清单。来源失败保留原原因，`sourceFailureMode="fail"`继续执行严格失败策略。调用者取消会停止原读取并确认进程退出，结果中的取消状态与时间预算耗尽分别处理。

| 数据端 | 定位时优先做什么 | 保留的范围说明 |
|---|---|---|
| Codex | 在读取预算内扫描物理日志窗口，复用已经完整验证的压缩视图 | 旧继承段、冷压缩视图或未读范围继续标为部分覆盖 |
| Claude Code | 已知目标直接定位文件，未知目标只读有界元数据，正文探针逐块检查预算 | 超出目录或读取预算的范围保留未核实状态 |
| Windsurf／Devin | 工作区及可见状态先筛选，先查物理会话的近期正文，再核桌面与CLI身份 | 主链窗口、子代理和未完成的别名关联分别说明 |
| Antigravity | 将来源预算传到PB与LS读取，定位只投影请求窗口 | 本地窗口已读、其它来源比较待完成分别说明 |
| DSH | 先读会话头部元数据，按需读取目标正文 | 单个坏来源与未检查会话分别报告 |

`list`是同步定位入口，到期后可缩小工作区或查询范围、调整`deadlineMs`继续定位；它没有`background`或`task_status`参数。需要后台深搜时使用`deep_locate`，沿首次返回的`taskId`调用`deep_locate_status`或`deep_locate_cancel`。`prepare`和`search_all`分别使用自己的状态、取消和恢复操作，保持原调用者身份，不把一次通信超时当作重新提交的依据。

Codex冷压缩原文需要完整解压和内容校验后才能做完整正文定位。有界探针会保留`compressed_source_requires_verified_view`与具体准备参数；先以目标ID调用`fetch(source="local", progressive=false, background=true)`，沿原后台任务等到完整缓存提交成功，再用`source="cache"`的`list/search/read`。已提交的同一generation可在新进程重用，缓存检索会保留原来源及覆盖。尚未准备的原始压缩来源继续显示部分状态。

## Codex近期窗口与旧历史

目标对话采用显式ordinal的明文追加段时，近期读取先使用对话元数据指定的当前段，核对session身份、头部声明、物理快照及记录顺序。较老压缩祖先尚未读取时，当前段已取得的正文可以先使用；它保留祖先的字节和ordinal边界声明，轮次按局部相对位置返回。

这种窗口的`sourceRangeVerified=false`、`requestedRangeComplete=false`和`fullSourceComplete=false`会继续保留，已发布的正文与固定`rangeRef`仍可读取。当前段不足所需轮数、来源在读取中变化或完整祖先核验受限时，结果说明实际覆盖及未完成部分，沿原任务继续查询，避免重复新建任务。完整fetch、Record和recall仍走原完整来源规则；压缩、记录、字节及内存上限保持。

## 其它同类修复

记忆关键词检索改为分批异步读取所需的正文前缀，保留原先前3000个UTF-16代码单元的匹配语义，减少为短预览读完整大文件的开销。旧Codex bridge的元数据/来源指纹使用已有异步入口。PDF附加文件的Python探测和嵌入改为有界异步子进程，并在进程关闭后结算。

Guard仍执行轻量单轮审查，原有模型输入/输出上限和目标绑定保持。对话执行证据的来源读取被隔离并可取消；参考证据和必需证据分别使用有界准备时间，覆盖缺口继续进入实际证据说明。

## 使用中的恢复

长任务继续使用首次返回的`taskId`查询、取消或恢复，不因一次宿主或broker超时重新提交。`prepare_status/prepare_cancel`、`search_all_status/search_all_cancel`与统一后台状态/取消入口保留原身份和归属检查。取消后的已发布范围及固定引用按原缓存协议继续读取。

如果整个后端已经失去响应，先保留任务与未知结果，再通过独立维护入口仅恢复目标组件。运行版本、安装入口和真实业务分别核验，恢复过程中不删除真实历史或原任务。发布验收同时覆盖真实定位、定点读取、并发轻请求和故意不合作的读取任务，不能只以目标已知后的快读作为整个定位流程的结论。
